An API Template is a starting point for a new Tyk OAS API. It is an Asset that Tyk Dashboard stores, and it contains some of the configuration of a Tyk OAS API definition. When you create an API from a Template, Tyk Dashboard copies the configuration in the Template into the new API.

The default Template is a blank API definition. Your custom Templates contain some configuration, for example cache configuration, or default endpoints with pre-configured middleware. When you create a new API from a custom Template, the elements of the API configuration in the Template are pre-configured for you.

<Note>
API Templates are exclusive to [Tyk OAS APIs](/api-management/gateway-config-introduction#api-definitions). You can manage them with the Tyk Dashboard API or in Tyk Dashboard.
</Note>

## When to Use API Templates

### Gateway Agnostic API Design

When you work with upstream services that have OpenAPI descriptions, your service developers don't need to learn about Tyk. You can create and maintain a set of Templates that contain the Tyk-specific configuration (`x-tyk-api-gateway`) that your published APIs need. To create an API on Tyk, you import the OpenAPI document and select the correct Template. Tyk combines the OpenAPI description with the Template to produce a valid Tyk OAS API.

### Standardizing API Configuration

Your external facing APIs can have specific requirements, for example authentication, caching or a health check endpoint. You can define API Templates that configure these fields correctly when you create APIs on Tyk.

## How API Templates Work

An API Template is a blueprint from which you build new APIs. It is an incomplete JSON representation of a Tyk OAS API definition. You use it as the starting point when you create a new API on Tyk. A Template can pre-configure as much or as little of the API definition as you need. The blank API definition that you start from when you don't choose a Template is itself a Template.

Tyk Dashboard applies Templates only when you create an API. You can't apply a Template to an existing API. Before you can use a Template as the basis for an API, you must register the Template with Tyk Dashboard.

### Structure of an API Template

An API template asset has the following structure:

| Field | Description |
| :--- | :--- |
| `id` | A unique identifier for the Template. |
| `kind` | The Asset type, which is `oas-template`. |
| `name` | A name for the Template. |
| `description` | A short description of the Template, for example to say what configuration it holds. |
| `data` | A Tyk OAS API definition. Tyk uses its content when you create an API from the Template. |
| `_id` | A unique identifier that Tyk assigns when it registers the Template in the Tyk Dashboard database. |

### Applying a Template

When you use a Template to [create](/api-management/gateway-config-managing-oas#creating-an-api) an API, the fields configured in `data` are pre-set in your new API. You can change them while you create the API and afterwards. Tyk doesn't create a link between the API and the Template. Changes that you make to the API don't affect the Template, and changes to the Template don't affect the API.

<Note>
Categories are not part of API Templates. You can't pre-configure them in a Template. Set the Categories when you create the API, or edit them afterwards.
</Note>

### Merging with an OpenAPI Description or Tyk OAS API Definition

When you use a Template to create an API by [importing](/api-management/gateway-config-managing-oas#importing-an-openapi-description-to-create-an-api) an OpenAPI document or a full Tyk OAS API definition, Tyk combines the Template with the imported document. If the Template contains the `x-tyk-api-gateway` extension, Tyk applies it to the new API.

Where the OpenAPI description and the Template configure the same field:

- For maps, such as `paths` and `components`, Tyk adds new keys alongside the keys from the Template. If a key in the OpenAPI description matches one in the Template, the OpenAPI description takes precedence.
- For arrays, such as `servers` and `tags`, the values in the OpenAPI description replace the values in the Template.

### Fragments in API Templates

From TYk 5.16.0, a Template can contain [Fragment](/platform-management/api-fragments) references in place of static configuration. When you create an API from the Template, Tyk Dashboard copies the references into the new API. The new API therefore stays linked to the Fragments, and receives any later changes to them.

This lets you combine the two. The Template sets up a new API. The Fragments in it keep shared configuration, such as security settings, the same across every API that you create from the Template.

Tyk Dashboard validates a Template with its Fragments resolved when you save the Template, and when you change a Fragment that the Template references. You can't delete a Fragment while a Template references it.

When you create a Template from an existing API, the Template keeps the Fragment references of the API.

## Use API Templates in Tyk Dashboard

API Templates are in the **Assets** section of the Tyk Dashboard menu, under **API Templates**. To see them, you need the `api_assets` [permission](/platform-management/user-permissions). This screen lists all the Templates registered with Tyk, with their names, Template IDs and descriptions. You can create and manage Templates from this screen.

<img src="/img/dashboard/api-assets/api-templates/api-templates-menu.png" alt="API Templates" />

### Create a Template

1. Go to **Assets > API Templates** and click **Add Template**.
2. On the **Create API Template** screen, in **Template info**, enter a **Template Name** and a **Template Description**. Both are required. The Template doesn't need to be a complete or valid API definition.
3. Configure the API-level settings on the **Settings** tab, and the endpoint-level settings on the **Endpoints** tab.

   <img src="/img/dashboard/api-assets/api-templates/create-api-template.png" alt="Configure the Template" />

4. Click **Save Template**.

The **API Templates** screen now lists your new Template, with its unique Template ID. You can use this ID to access the Template with the [Tyk Dashboard API](#use-api-templates-with-the-tyk-dashboard-api).

### Create a Template from an API

You can use an existing API deployed on Tyk as the basis for a new API Template. This is a good way to build up a portfolio of standardized APIs once you've configured your first API correctly.

1. Open the API that you want to use as your starting point.
2. Click **Actions** and select **Create API template**.

   <img src="/img/dashboard/api-assets/api-templates/create-from-api.png" alt="Create a new Template from an existing API" />

3. On the **Create API Template** screen, enter a **Template Name** and a **Template Description**.
4. Change any of the API-level and endpoint-level settings that you need.
5. Click **Save Template**.

If the API uses Fragments, the Template keeps the Fragment references.

### Create an API from a Template

You can base a new API on a Template in two ways:

- Go to **Assets > API Templates**. For the Template that you want to use, open the **Actions** menu and select **Create API from Template**.

  <img src="/img/dashboard/api-assets/api-templates/create-api-from-template.png" alt="Select Create API from Template" />

- Go to the APIs list and click **Add New API**. In the **API Style** step, select an HTTP API with Tyk OAS, then select the Template in the **API Templates** step. Tyk Dashboard shows this step only when at least one Template exists.

  <img src="/img/dashboard/api-assets/api-templates/create-api-from-template2.png" alt="Select the Template you want to use" />

Both ways take you to the API Designer, where the settings from your Template are pre-configured. To create an API from a Template, you need write access to APIs.

### Import an API with a Template

On the **Import API** screen, select the OpenAPI type to create an API from an OpenAPI description or Tyk OAS API definition. Provide the document to Tyk Dashboard in one of these ways:

- **Paste API Definition**: paste the JSON into the text editor
- **Import from File**: upload a file that contains the JSON
- **Pull from URL**: provide a URL to the JSON

Then select the Template that you want to use in the **Template name** field, above **Manual configuration options**:

<img src="/img/dashboard/api-assets/api-templates/import-select-template.png" alt="Select the Template you want to use" />

### Edit a Template

1. Go to **Assets > API Templates**.
2. Click the name of the Template, or open its **Actions** menu and select **Edit Template**. If you have only read access to Templates, the menu item is **View Template**.
3. On the **API Template Details** screen, click **Edit**, and change the settings.

   To view and change the raw JSON of the Template, open the **Actions** menu and select **View Raw Template**. To return to the form, select **View Template Designer**.
4. Click **Save Template**.

### Delete a Template

1. Go to **Assets > API Templates** and open the Template.
2. On the **API Template Details** screen, open the **Actions** menu and select **Delete Template**.
3. Confirm the deletion.

<Note>
You can't undo the deletion. Tyk Dashboard removes the Template from its database, and you can't recover it.
</Note>

## Use API Templates with the Tyk Dashboard API

With the Tyk Dashboard API, you can [register a Template](#register-a-template), and [apply it](#apply-a-template-to-a-new-api) when you create an API from an OpenAPI description or a Tyk OAS API definition.

### Register a Template

To register an API Template, send the Asset in the body of a `POST` request to the `/api/assets` endpoint of Tyk Dashboard. For example, this Template enables caching for the whole API, and adds a `POST /anything` endpoint with a request size limit:

```bash
curl -X POST "https://{DASHBOARD_URL}/api/assets" \
  -H "Authorization: {DASHBOARD_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "kind": "oas-template",
    "id": "my-unique-template-id",
    "name": "my-template",
    "description": "My first template",
    "data": {
      "openapi": "3.0.3",
      "info": { "title": "", "version": "" },
      "paths": {
        "/anything": {
          "post": {
            "operationId": "anythingpost",
            "responses": { "200": { "description": "" } }
          }
        }
      },
      "x-tyk-api-gateway": {
        "middleware": {
          "global": {
            "cache": { "enabled": true, "timeout": 5, "cacheAllSafeRequests": true }
          },
          "operations": {
            "anythingpost": {
              "requestSizeLimit": { "enabled": true, "value": 100 }
            }
          }
        }
      }
    }
  }'
```

Tyk Dashboard responds with `201 Created`. In the response, `ID` contains the Template `id`, and `Meta` contains the database ID (`_id`) of the Template. If you don't provide an `id`, Tyk Dashboard generates one.

### Apply a Template to a New API

To apply a Template when you create an API, add the `templateID` query parameter to the request. Its value is the `id` or the database ID (`_id`) of the Template. You can use it with these endpoints:

| Endpoint | Creates an API from |
| :--- | :--- |
| `POST /api/apis/oas/import` | An OpenAPI description |
| `POST /api/apis/oas` | A Tyk OAS API definition, with the `x-tyk-api-gateway` extension |

Tyk Dashboard combines the document in the request with the Template, using the rules in [Merging with an OpenAPI Description or Tyk OAS API Definition](#merging-with-an-openapi-description-or-tyk-oas-api-definition).

For example, this request imports an OpenAPI description with a `GET /xml` endpoint, and applies the Template from the previous example:

```bash
curl -X POST "https://{DASHBOARD_URL}/api/apis/oas/import?templateID=my-unique-template-id" \
  -H "Authorization: {DASHBOARD_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "openapi": "3.0.3",
    "info": { "title": "my-open-api-document", "version": "1.0.0" },
    "servers": [{ "url": "http://httpbin.org" }],
    "paths": {
      "/xml": {
        "get": {
          "operationId": "xmlget",
          "responses": { "200": { "description": "" } }
        }
      }
    }
  }'
```

Tyk Dashboard responds with `200 OK`. In the response, `ID` contains the API ID, and `Meta` contains the database ID of the new API.

The new API has:

- the `GET /xml` endpoint from the OpenAPI description, and the `POST /anything` endpoint with its request size limit from the Template
- caching for the whole API, from the Template
- the `servers` entry from the OpenAPI description, which points to the upstream service, with the API URL on Tyk Gateway added, as described in [Modifying the OpenAPI Description](/api-management/gateway-config-tyk-oas#modifying-the-openapi-description)

## Use API Templates with Tyk Sync

[Tyk Sync](/api-management/automations/sync#working-with-api-templates-and-api-fragments) 1.5 and later can dump, publish and sync API Templates together with your APIs and Policies.
