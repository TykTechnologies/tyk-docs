**This page contains all release notes for Tyk AI Studio, displayed in reverse chronological order.** Each release covers the AI Studio control plane, the Edge Gateway, and the bundled enterprise and community plugins.

Tyk AI Studio is available as a [Community edition](/ai-management/ai-studio/overview#community-edition) (open source) and an [Enterprise edition](/ai-management/ai-studio/overview#enterprise-edition).

## 2.3 Release Notes

### 2.3.0 Release Notes

#### Release Date xx

#### Release Highlights

Tyk AI Studio 2.3.0 is for teams that run AI agents. You can see what each agent does, step by step, with no change to the agent. Guardrails protect agents from prompt injection in the pages, files, and API responses that they read. A new plugin reduces what agents spend on tokens. This release also adds FIPS 140-3 builds, decision models, and governed native SDK features from OpenAI and Anthropic. Other additions are MCP governance on open-source Tyk Gateways, active-active control planes, and Workspaces. It also changes several defaults to make deployments safer.

This is not a rolling upgrade. You must stop every AI Studio replica before the first 2.3 replica starts, and some changes cannot be undone without a database backup. Enterprise deployments also need a new license. Read the Breaking Changes and Upgrade Instructions sections below before you upgrade.

**Agent Call Tracing (Enterprise)**

AI Studio turns the traffic that the gateway already sees into a readable record of each agent session. The **Agent sessions** page lists sessions, and shows a transcript and a timeline for each one. The record includes LLM calls, tool calls, MCP calls, and data source queries, on AI Studio and on Edge Gateways. It also shows the decisions of the gateway, such as a filter block, a budget block, a failover, or a routing choice. You do not need an SDK or code changes in the agent.

Tracing is off by default. Content capture is a separate setting (`off`, `metadata`, `redacted`, or `full`), and AI Studio always removes secrets and encrypts captured content at rest. You can export traces over OpenTelemetry, with presets for Langfuse and Datadog LLM Observability.

**Guardrails for Agent Traffic (Enterprise)**

Agents read web pages, files, and API responses. Any of these can contain hidden instructions (indirect prompt injection). In 2.3, [guardrails](/ai-management/ai-studio/guardrails) inspect every part of an agent conversation:

- **Tool results.** Request guardrails scan all tool results in the conversation history, in every vendor format.
- **Quarantine.** The new `quarantine` action replaces only the flagged tool result with a placeholder. The agent continues without it.
- **Tool calls and tool definitions** (opt-in). A guardrail can refuse a dangerous tool call before the client runs it, and remove a poisoned tool description before the model sees it.
- **Shadow mode.** Test a guardrail on live traffic with no added latency.
- **Fewer false positives.** Administrators can approve trusted prompt templates for an App, and create guardrail exceptions for one App from a flagged event. An LLM judge can give a second opinion on prompt-injection findings.

Two open-source images run the Wolf Defender classifier as an HTTP guardrail provider, on CPU or on NVIDIA GPUs.

**Prompt Compressor (Community Plugin)**

The new Prompt Compressor plugin makes agent requests smaller on Edge Gateways before they reach the vendor, so you pay for fewer input tokens. The same input always gives the same output, so the prompt cache of the vendor continues to work. The plugin starts in audit mode: it records what it would save and sends the original request. A dashboard shows the tokens and cost that you save.

**FIPS 140-3 Builds**

AI Studio and the Edge Gateway are available as FIPS 140-3 compliant builds, as packages and as container images. They use the Go Cryptographic Module v1.0.0 ([CMVP certificate #5247](https://csrc.nist.gov/projects/cryptographic-module-validation-program/certificate/5247)). A database can move between standard and FIPS builds.

**Decision Models and Native SDK Features**

AI Studio governs decision models. A decision model answers typed questions about evidence with calibrated probabilities. Clients call one OpenAI-compatible endpoint (`POST /v1/decisions`) for OpenAI and System One models.

Anthropic Message Batches and `count_tokens`, and the OpenAI Responses, Conversations, Batches, and Files APIs, work through the native `/llm/` endpoints. They use the same model allow-lists, filters, budgets, and analytics as chat calls. Each batch, file, response, and conversation belongs to the App that created it.

**MCP on Open-Source Tyk Gateways (Enterprise)**

AI Studio can manage MCP proxies and keys directly on open-source Tyk Gateways (5.13 or later), with no Tyk Dashboard. Tyk Pump can also send Tyk Gateway analytics to AI Studio, so each MCP server has a **Usage** tab and the dashboard has an **MCP traffic** panel. See [Tyk MCP Integration](/ai-management/ai-studio/tyk-mcp-integration).

**Active-Active Control Planes**

You can run AI Studio in two regions with one replicated PostgreSQL database. AI Studio follows a database failover without a restart. Edge Gateways can use several control planes. They can also start from their last known configuration when no control plane answers. In the Enterprise edition, they can validate App keys from a hashed list while no control plane is available.

**Workspaces and Service Accounts**

Every configuration object belongs to a Workspace. In the Enterprise edition, you can give a team, user, or service account a role within one Workspace. That role applies only to the objects of that Workspace. Roles assigned before the upgrade stay global, so nothing changes until you create a Workspace. Service accounts are users for automation, such as a CI pipeline or a script, that sign in with an API key only. A push to Edge Gateways can carry the changes of one Workspace only.

#### Breaking Changes

This release changes several defaults, the database, and some API behavior. Check each item against your deployment. The Upgrade Instructions section below gives the steps in order.

**License and Database**

- **Enterprise needs a license issued for 2.3.** AI Studio and Enterprise Edge Gateways do not start with a license issued for 2.2 or earlier, even if it has not expired. AI Studio stops with `license validation failed at boot: invalid license: license does not include the Tyk AI Studio SKU`. The new license also limits Edge Gateway namespaces, admin users, AI Portal users, Apps, and LLMs. Over a limit, AI Studio removes nothing, but refuses new objects with `409 QUOTA_EXCEEDED`.
- **App keys are hashed and encrypted at the first start, and this is one-way.** After the first 2.3 start, an older AI Studio cannot use the database. An older AI Studio that starts on it refuses every App key (`Invalid token`) and sends the encrypted form of each literal LLM key to vendors. To roll back, you must restore a backup.
- **Do not change `TYK_AI_SECRET_KEY` after the upgrade.** AI Studio finds App keys by a hash made with this key, and encrypts LLM credentials with it. If the value changes, every App key stops validating and stored credentials cannot be read. The database also holds a new salt (table `data_key_salts`) that App keys need. Do not restore or copy the `credentials` table without it.
- **SQLite runs in WAL mode.** AI Studio creates `-wal` and `-shm` files next to the database, so the directory must be writable. A copy of the database file alone is not a complete backup. On a network file system, set `_journal_mode=DELETE` in `DATABASE_URL`.

**Network and Credentials**

- **Internal network addresses are blocked by default.** `LLM_UPSTREAM_BLOCK_INTERNAL` now defaults to `true` on AI Studio and on Edge Gateways. More ranges also count as internal, such as shared address space (`100.64.0.0/10`, which Tailscale and some Kubernetes CNIs use). See Upgrade step 2.
- **`$ENV/` references resolve only for allowed names.** AI Studio never sends an unresolved LLM key, embedder key, or REST tool key. The gateway returns `502` (`LLM credential not usable`). See Upgrade step 3.
- **Vendor keys are no longer read from environment variables**, such as `OPENAI_API_KEY` or `OLLAMA_HOST`. Set the key or endpoint on each LLM, embedder, and data source. See Upgrade step 4.
- **SSO needs `TYK_AI_SECRET_KEY`.** Without it, AI Studio refuses every SSO login.
- **Setting or changing a `$SECRET/` or `$ENV/` reference needs the `secrets:read` permission.** Without it, the API returns `403`.
- **The quickstart ships placeholders instead of sample secrets.** AI Studio does not start until you replace the `__REPLACE_WITH_…__` values.
- **API keys are shown in full only when they are issued.** The users API (`/api/v1/users`) no longer returns `api_key`, also for administrators. It returns `api_key_hint` (the last four characters) and `has_api_key`. See Upgrade step 10.
- **Data source connection strings show their password as `[redacted]`.** If you change a connection string that still contains `[redacted]`, the API returns `422`. Type the password again when you change the host or user.
- **Marketplace indexes on an internal address are refused.** Sync and validation errors do not give the cause. Look for `Marketplace fetch failed` in the AI Studio log. See Upgrade step 2.
- **Standalone Edge Gateway API tokens are hashed at rest, and this is one-way.** A version before 2.3 accepts none of the tokens afterwards. Changing `ENCRYPTION_KEY` now invalidates every API token.

**Plugins**

- **OCI plugins must be signed (Enterprise).** `AI_STUDIO_OCI_REQUIRE_SIGNATURE` now defaults to `true`, and the Helm charts also require signatures. Transparency-log entries are also required by default. The `cosign` binary is no longer shipped or needed at runtime, and cosign policy files are no longer supported. The Community Edition cannot verify signatures. It loads OCI plugins as unverified and logs a warning.
- **Plugins no longer inherit the environment of the host.** The github-rag-ingest plugin is the only shipped plugin that this affects. See Upgrade step 6.
- **Plugins get only the scopes that they declare.** AI Studio refuses a service API call outside the approved scopes of the plugin.
- **Plugins on an internal registry or host are refused**, including installed plugins, unless you list the host in `LLM_UPSTREAM_ALLOWED_INTERNAL_HOSTS`. `PLUGIN_BLOCK_INTERNAL_URLS` is deprecated.
- **Request-path plugins built on an older SDK keep a 4 MiB message limit.** Larger requests get `413`. Rebuild your plugins on the 2.3 SDK, and install the 2.3.0 releases of the shipped plugins.
- **Plugins and filter scripts on Bedrock LLMs see the Bedrock Converse format** on `/ai/`, `/v1`, routers, and `/anthropic/`. Filter scripts get `input.format == "bedrock"`.
- **Edge Gateways refuse traffic for an LLM with a plugin that cannot load.** Requests to that LLM get `503` (`plugin_load_failed`) with `Retry-After: 30`. Before 2.3, the Edge Gateway skipped all plugins of the LLM. You cannot turn this off. Other LLMs are not affected, and `/ready` stays `200`. See Upgrade step 6.
- **Changing the command of a plugin withdraws the approval of its scopes.** This applies to a new file path, `grpc://` address, or OCI reference, in the console or with `PATCH /api/v1/plugins/{id}`. AI Studio stops the old process and loads the new binary. The plugin has no service access in AI Studio until an administrator approves its scopes again. This also applies when the scopes did not change.
- **Plugins no longer see credentials.** System events and object hooks show LLM, tool, data source, and user credentials as `[redacted]`. An LLM in a `system.llm.*` event or an object hook lists its plugins with `config: null`, and a hook cannot change that configuration. `system.plugin.*` events show the secret fields of the plugin as `[redacted]`.
- **The plugin UI registries no longer return plugin configuration to most users.** `GET /api/v1/plugins/ui-registry` returns the configuration (with secret fields as `[redacted]`) and the command only to users with `plugins:read`. `GET /common/plugins/portal-ui-registry` never returns them. A plugin page that reads its configuration from the registry must get it from its plugin.
- **For plugin authors and Go embedders:** `models.LLMVendorProvider` has two new methods, `ProvidesChat()` and `DecisionEndpoint()`. `CallLLM` returns `FailedPrecondition` when the App of the agent has no credential. Request IDs now have the format `tyai_` followed by a UUIDv7.

**Guardrails (Enterprise)**

- **Existing request guardrails start to scan tool results.** For tool results, a `block` action becomes `quarantine`. To keep a guardrail as it was, clear **Scan tool results**.
- **Remote guardrail providers start to receive tool output.** Tool output can contain file contents, database rows, and credentials. Lakera Guard and Bedrock Guardrails now get one call for each message and tool result, so they can cost more.
- **Guardrail block messages are longer.** They now end with the reason, a reason code, and a request ID. Match on `reason_code` or the `X-Tyk-AI-Guardrail-Reason` header instead of the message text.
- **Fail-open is narrower for large requests.** If a provider fails on text over `single_call_chars` (32,768 characters), the text is unscanned and the action of the filter applies.

**Edge Gateways**

- **Edge Gateways older than 2.3 do not work fully with AI Studio 2.3.** They block traffic that guardrails protect, fail Bedrock calls, cannot serve decision models, and do not enforce LLM budgets. Upgrade them together with AI Studio.
- **Edge Gateways return `404` on `/api/v1`.** The `mgw` CLI no longer works against an Edge Gateway. Configure Edge Gateways from AI Studio.
- **The request ID header is `X-Tyk-AI-Request-ID`.** Edge Gateways no longer overwrite `X-Request-ID`.
- **Edge Gateways run the plugins of an LLM in the order set in AI Studio.** Before 2.3, they used the install order.
- **Policy blocks and errors on Edge Gateways now appear in the request logs of AI Studio**, as rows with no spend. Request counts include them.
- **Edge Gateways store their last applied configuration** in a new table, `applied_snapshots`. It can be up to 16 MB.

**OpenAI and Native APIs**

- **OpenAI response IDs issued before 2.3 no longer verify.** The first call returns `404`, and the client starts a new chain.
- **`/v1/responses` and batch lines must name a `model`.**
- **`/v1/files` accepts only `purpose=batch` uploads.** On an LLM with request filters, re-upload batch files from before 2.3.
- **With request filters attached, unreadable input is refused with `400`.**
- **`/ai/` and `/v1` forward more request parameters to OpenAI.** `user`, `safety_identifier`, `prompt_cache_key`, `store`, `service_tier`, `parallel_tool_calls`, `logprobs`, `top_logprobs`, `top_p`, and a list of `stop` sequences reach OpenAI as the client sent them, as on `/llm/`. Before 2.3, these endpoints dropped them. Check clients that set them. For example, `store: true` stores the completion at OpenAI, and `service_tier: flex` or `priority` is served and billed at that tier. A model that does not accept a parameter returns the `400` of the vendor. For example, `gpt-5.5` refuses a list of `stop` sequences. Anthropic, Google, and Bedrock get only `stop` and `top_p`.
- **`/ai/` and `/v1` apply `tool_choice` for Anthropic, Google, and Bedrock, and refuse values that they cannot apply.** Before 2.3, these endpoints dropped the value for these vendors. They now return `400` before any vendor call for these values:
  - A string other than `auto`, `none`, or `required`
  - An object that is not `{"type":"function","function":{"name":...}}`, such as `allowed_tools` or `custom` from OpenAI
  - A named function that is not in the `tools` of the request
  - `required` without `tools`

  OpenAI-compatible vendors are not affected.
- **Some headers are no longer forwarded:** `OpenAI-Organization`, `OpenAI-Project`, `anthropic-user-profile-id`, and a client's `anthropic-workspace-id`. Use the Anthropic workspace setting of the LLM instead.

**Chat**

- **Model call settings no longer send `temperature` and `top_p` by default.** The value `0` means "not sent". Call settings saved before 2.3 keep their values. For Claude Sonnet 5 and later, set both to `0`, or Studio Chat fails with `400`.
- **Chat sessions send their history.** On LLM settings without a maximum length, a session now sends up to the newest 100 messages. Set **Max Length** to limit the input.
- **Chat no longer shows images from model responses by default.** Turn on **Render images in responses** for chats that need images.
- **Chat costs change.** Anthropic turns with tool calls or thinking now cost the correct amount, and cached tokens are billed at the cache price.

**API and Deployment**

- **Chat and AI Portal agent responses no longer contain credentials or configuration.** The first event of a chat stream lists tools and data sources by ID, name, and description only. `GET /common/agents` returns only `plugin_id` and `app_id` for the plugin and App of an agent. Update integrations that read these values.
- **Telemetry to Tyk is off by default.** Before 2.3, AI Studio sent usage telemetry, and the Enterprise edition sent license usage reports, unless you turned them off. To send usage telemetry, set `TELEMETRY_ENABLED=true` (Helm: `config.telemetryEnabled`). To send license usage reports (Enterprise), set `LICENSE_DISABLE_TELEMETRY=false` (Helm: `config.licenseTelemetryEnabled`).
- **Recorded Anthropic spend can increase.** AI Studio now records and bills non-streamed Anthropic responses with a thinking block. This also applies to other blocks that are not text or `tool_use`. Response filters and guardrails also screen the text blocks of these responses.
- **Tool and LLM names must be unique**, ignoring case, spaces, and punctuation. Duplicates stored before 2.3 stay editable.
- **AI Studio returns `503 database_unavailable` during a database outage.** Management API requests that returned `500`, and sign-in and session checks that returned `401`, now return `503` with `Retry-After`.
- **`/ready` no longer fails as soon as PostgreSQL stops answering.** It stays `200` for `DATABASE_READY_GRACE` (30 seconds). Set it to `0` for the 2.2 behavior.
- **The AI Studio Helm chart honors `replicaCount`.** If your values set it above 1, the chart fails to render unless the database is external and `config.csrfKey` is set.
- **The Edge Gateway Helm chart now gives each pod 1Gi of memory** (it was 512Mi) and requests 256Mi (it was 128Mi). The pods are recreated on upgrade.
- **A Helm install with `nameOverride` or `fullnameOverride` and no Edge Gateway control endpoint now fails `helm upgrade`.** The message names the value to set.
- **The custom logo and favicon move into the database.** AI Studio imports them once, at the first start.
- **Decision models need a price.** Calls to a model with no price are recorded at zero cost.
- **The advanced-llm-cache plugin (1.3.0 and later) starts with an empty cache**, and Redis `tls_enabled` now takes effect.

#### Upgrade Instructions

The upgrade to 2.3 has three stages: prepare, upgrade, and check. Do the steps in order. Plan a maintenance window, because AI Studio is down in every region from when the last older replica stops until a 2.3 replica is ready. Edge Gateways continue to serve traffic during this time.

**Prepare (Before You Stop AI Studio)**

1. **Get a 2.3 license (Enterprise).** Ask your account manager for a license issued for 2.3. Keep your 2.2 license until the upgrade is confirmed. You need it if you roll back. The Community Edition needs no license.

2. **Allow the internal hosts that AI Studio must reach.** Find each object that runs on your own network, such as a local Ollama at `http://localhost:11434` or an in-cluster model server. This applies to LLMs, embedders, tools, data sources, vector stores, guardrail providers, plugin registries, marketplace indexes, and MCP servers. Then do one of these:
   - Recommended: list the hosts in `LLM_UPSTREAM_ALLOWED_INTERNAL_HOSTS` (comma-separated). The value `.svc.cluster.local` matches every Kubernetes Service. With Helm, use `config.allowedInternalHosts`.
   - After the upgrade, an administrator turns on **Allow internal host** on that object. This exempts only its own host.
   - Set `LLM_UPSTREAM_BLOCK_INTERNAL=false` to keep the 2.2 behavior.

   Set the same values on every Edge Gateway, because each process uses its own setting. A value that is not a boolean, such as `yes`, now stops startup. If you set `LLM_UPSTREAM_ALLOWED_HOSTS`, add the host of each marketplace index to it.

3. **Find your `$ENV/` references and allow them.** List the names that your configuration uses:

   ```bash
   pg_dump --data-only "$DATABASE_URL" | grep -oE '\$ENV/[A-Za-z_][A-Za-z0-9_]*' | sort -u
   ```

   For SQLite, use `sqlite3 midsommar.db .dump` instead of `pg_dump`. Add the names to `AI_STUDIO_ENV_REF_ALLOWLIST`, or move the values to the secret store and use `$SECRET/` references. Plugin configuration resolves only `$SECRET/` references.

4. **Set vendor keys on each object.** If an LLM, embedder, or data source has an empty key or endpoint and relies on `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GOOGLE_API_KEY`, `HF_TOKEN`, `PINECONE_API_KEY`, `CHROMA_URL`, or `OLLAMA_HOST`, set the key or endpoint on the object. Do not set these variables on Edge Gateways, because older Edge Gateways still read them.

5. **Set `TYK_AI_SECRET_KEY`.** Set it on every AI Studio replica, with the same value. SSO needs it, and it encrypts LLM credentials and App keys at rest. Store the value safely, and never change it after the upgrade. If you use the quickstart, replace each `__REPLACE_WITH_…__` placeholder (`TYK_AI_SECRET_KEY`, `MICROGATEWAY_ENCRYPTION_KEY`, and `GRPC_AUTH_TOKEN`) with a value that you generate. Also replace values that you copied from an earlier quickstart or documentation sample.

6. **Prepare your plugins.**
   1. **Signatures (Enterprise).** Sign your OCI plugins (`tools/publish-plugin.sh` does this) and configure their public keys with `OCI_PLUGINS_PUBKEY_<NAME>` on AI Studio and every Edge Gateway. To trust a third-party publisher, add their key in the same way. To load unsigned plugins, set `AI_STUDIO_OCI_REQUIRE_SIGNATURE=false`. For plugins signed without a transparency-log entry, such as air-gapped signing, set `AI_STUDIO_OCI_TLOG_POLICY` and `OCI_PLUGINS_TLOG_POLICY` to `disabled`.
   2. **Environment.** List the host variables that each plugin needs in `PLUGIN_ENV_PASSTHROUGH`. If you set `GITHUB_RAG_SECRET_ENCRYPTION_KEY` or `GITHUB_RAG_KNOWN_HOSTS`, add `PLUGIN_ENV_PASSTHROUGH=GITHUB_RAG_*`, or set `secret_encryption_key` and `known_hosts_path` in the plugin configuration. Without the key, github-rag-ingest stores new credentials unencrypted.
   3. **Registries.** If a plugin registry is on an internal address, list it in `LLM_UPSTREAM_ALLOWED_INTERNAL_HOSTS` on AI Studio and every Edge Gateway. On proxy-only networks, also list the hosts that the registry redirects downloads to. For `docker.tyk.io`, use `docker.tyk.io,dl.cloudsmith.io`.
   4. **Versions.** Plan to install the 2.3.0 releases of the shipped plugins (see **Updated the shipped plugins for 2.3** in the Changelog). Rebuild your own request-path plugins on the 2.3 Plugin SDK. For Bedrock, use the SDK helpers `RequestModel`, `IsStreamingRequest`, and `ResponseUsage`.
   5. **Order.** Check the plugin order on each LLM that has more than one plugin. Edge Gateways now use this order.
   6. **Loading on Edge Gateways.** Make sure that every plugin attached to an LLM loads on each Edge Gateway. Check the signatures and keys, `PLUGINS_ALLOWED_SOURCES`, and internal hosts. If a plugin does not load, the Edge Gateway logs `Plugin could not be loaded` with the cause.

7. **Check filter scripts on Bedrock LLMs.** Scripts now get the Bedrock Converse format (`input.format == "bedrock"`). Read `input.messages`, or handle the Converse format.

8. **Decide how guardrails treat tool results (Enterprise).** Existing request guardrails start to scan tool results after the upgrade, and remote providers start to receive tool output. If a provider must not see tool output, plan to clear **Scan tool results** on that guardrail (`"tool_results": {"scan": false}`) and use a scope other than `all_messages`. On a 2-CPU host, set `GUARDRAIL_LOCAL_SCAN_SLOTS=1`, or run gateways that scan agent traffic on 4 or more CPUs.

9. **Update clients of the native OpenAI APIs.** Make sure that `/v1/responses` requests and batch lines name a `model`. Plan to re-upload batch files on LLMs with request filters. Replace the `OpenAI-Organization`, `OpenAI-Project`, and `anthropic-workspace-id` headers with the workspace setting of the LLM. On `/ai/` and `/v1`, check clients that set OpenAI parameters such as `store` or `service_tier`. Also check clients that force a `tool_choice` function that is not in their `tools`.

10. **Update scripts that read credentials.** The users API no longer returns API keys. Store each key when you issue or roll it. To get a key that you can copy, roll the key. Also update integrations that read tool or data source credentials from chat events, or agent configuration from `/common/agents`.

11. **Size your Edge Gateways.** Edge Gateways now keep undelivered analytics in memory during a control-plane outage. Allow the working set of the Edge Gateway, plus the backlog (64 MiB with the Helm chart, 256 MiB without it), plus about 50 MB. If you set your own Helm resources, check that they leave room for this.

12. **Prepare the Helm values.**
    - AI Studio chart with `replicaCount` above 1: set `midsommar.strategy.type: Recreate` for this upgrade, or scale to one replica. You need an external database and `config.csrfKey`.
    - If you use `nameOverride` or `fullnameOverride` with the bundled Edge Gateway, set `microgateway.config.controlEndpoint`, or set `microgateway.enabled: false`.
    - `config.ociRequireSignature: false` now works as a boolean.

13. **Back up the database.** A backup is the only way to roll back.
    - PostgreSQL: take a full backup. It must include the `credentials` table.
    - SQLite on 2.2: stop AI Studio and copy `midsommar.db`. A 2.2 database has no `-wal` file, so the copy is complete.

**Upgrade**

14. **Stop every older AI Studio replica, in every region.** No older replica can run on the database after the first 2.3 replica starts. An older replica that shares the database refuses every App key, and can become the cluster leader.

15. **Set the 2.3 license.** Set `TYK_AI_LICENSE` on every AI Studio replica, with the same license, and on every Enterprise Edge Gateway.

16. **Start the first 2.3 replica.**
    - Keep the branding directory (`BRANDING_STORAGE_PATH`, default `./data/branding`) in place. AI Studio imports the custom logo and favicon once, and logs `Branding: imported the logo from …`.
    - Wait for the migrations to finish before you start other replicas. Converting App keys takes about 1.5 seconds for each 10,000 keys on SQLite, and about 7 seconds on PostgreSQL.
    - On PostgreSQL, AI Studio waits up to `DATABASE_STARTUP_TIMEOUT` (60 seconds) for a writable database. Neither `/health` nor `/ready` answers during this time. On Kubernetes, use a startup probe that allows for this time plus the migrations. The Helm chart adds one.
    - On the first start, AI Studio downloads each cached plugin again to record its hash. Make sure that the registry is reachable. The log line `Cached OCI plugin failed its integrity check, fetching it again` is expected.

17. **Start the other AI Studio replicas.** Give every replica the same `CSRF_KEY`, `TYK_AI_SECRET_KEY`, `MICROGATEWAY_ENCRYPTION_KEY`, and `GRPC_AUTH_TOKEN`. The cluster status (`GET /api/v1/cluster/status`) warns when they differ.

18. **Upgrade your Edge Gateways.**
    - Upgrade AI Studio first. Then upgrade each Edge Gateway as soon as AI Studio is ready. Edge Gateways older than 2.3 do not work fully with AI Studio 2.3.
    - Upgrade every standalone Edge Gateway that shares a database at the same time. The first 2.3 Edge Gateway hashes the stored API tokens. `./microgateway -migrate` now needs `TYK_AI_LICENSE` on Enterprise.
    - Edge Gateways resync when they reconnect. An Edge Gateway that starts without local configuration shows **Pending** until you push the configuration.

19. **Install the 2.3.0 releases of the shipped plugins.** Approve new plugin scopes when AI Studio asks. For example, advanced-llm-cache now needs `apps.write`. When you change the command of a plugin, approve its scopes again. A 2.3 Edge Gateway replaces a plugin whose command changed at the next configuration push, with no restart. If the new binary does not load, the Edge Gateway stops the plugin and refuses requests to its LLMs.

**Check**

20. **Check the license (Enterprise).** Go to **Admin > Settings > License** to see the limits and your current usage.

21. **Check credentials.** Look for LLMs, tools, and data sources that show an unresolved credential, and for `502 LLM credential not usable` responses.

22. **Check Edge Gateways.** Push the configuration, and check that each Edge Gateway shows **In sync**. If a push lists skipped entries, rename the duplicate tool or LLM names that AI Studio logs. Move filters and plugins that an LLM in another namespace needs to the global namespace or to the namespace of the LLM. If an LLM returns `503` (`plugin_load_failed`), find the cause in the Edge Gateway log. The `plugins_not_ready` field of `/ready` also lists the plugin, because pod readiness does not show the failure.

23. **Turn on the new features that you want.** New features are off by default, such as `AGENT_TRACING_ENABLED`, `CONTROL_ENDPOINTS`, `EDGE_START_FROM_LAST_KNOWN_GOOD`, and `EDGE_CREDENTIAL_SYNC=full`. If you turn on Agent Call Tracing, also set `AGENT_TRACING_CONTENT_CEILING`. When it is not set, the ceiling is `metadata`, and it overrides Apps set to Redacted or Full. To use Workspaces (Enterprise), create them after the upgrade. Until then, every object is in the Default Workspace and every role stays global.

After this upgrade, later upgrades of AI Studio with several replicas can roll.

**Roll Back**

To roll back to 2.2, you must restore the backup. Anything changed after the upgrade is lost.

1. Stop every AI Studio replica.
2. Restore the backup that you took before the upgrade.
   - For SQLite, delete `midsommar.db-wal` and `midsommar.db-shm` first, then copy the backup over `midsommar.db`. A leftover `-wal` file corrupts the restored copy (`database disk image is malformed`). Keep the original backup file until the restored database starts.
3. Start 2.2 with your 2.2 license.

If you used Workspaces or service accounts, these change on 2.2:

- Roles assigned within a Workspace grant nothing.
- Service accounts keep working with their API keys, without the restrictions of a service account.
- The users API returns full API keys again to callers who can read users.

If 2.3 did not start because the license was refused, AI Studio did not change the database. You can start 2.2 again on it without a restore.

To back up a running 2.3 SQLite database later, use `sqlite3 midsommar.db ".backup backup.db"` or `VACUUM INTO`.

#### Known Issues

- **Model Routers and Semantic Routers do not route decision calls yet.** They return `400`.
- **Studio Chat cannot use a Bedrock LLM.** This is not new in 2.3.
- **Some OpenAI IDs are not checked for ownership.** A `file_id` in an `input_file` or `input_image` part, and an `item_reference` ID, go to OpenAI unchecked. Filters do not screen `input_file` content.
- **Guardrails do not inspect some content:**
  - Binary documents, such as PDF and Word, and images
  - Files that are referenced by ID, and conversation state that the vendor holds
  - The results of tools that the vendor runs within one call
  - Data source context in Studio Chat
- **The built-in injection heuristics are a baseline.** Use them together with Lakera Guard, Azure Prompt Shields, Bedrock Guardrails, or the Wolf Defender images.
- **Standalone Edge Gateways sign resource IDs with the vendor API key.** Rotating that key invalidates outstanding IDs.
- **The analytics backlog of an Edge Gateway is in memory.** If the Edge Gateway restarts during a control-plane outage, the backlog is lost. Do not restart Edge Gateways during an outage, and alert on `microgateway_analytics_pulse_dropped_records_total{reason="over_backlog"}`.
- **A revocation does not reach an Edge Gateway that cannot reach any control plane.** The Edge Gateway serves its last known configuration until it reconnects.
- **AI Studio does not queue writes after the retry window.** If the database has no primary for longer than `DATABASE_WRITE_RETRY_WINDOW` (15 seconds), writes fail with `503`. Clients must retry after `Retry-After`.
- **Script filters see tool results as sent.** Guardrails decode tool results, but script filters do not. An empty `input.segments` with a non-empty `raw_input` means an unreadable body. A script that screens tool results must block it.
- **Workspaces control who can change an object, not who can use it (Enterprise).** An App linked to a model provider, tool, or data source in another Workspace uses it, including its credentials.
- **File store content is readable from every Workspace.** Do not keep secrets in file stores.
- **Tyk connections are global.** They do not belong to a Workspace.
- **Unique names are unique across Workspaces.** A name conflict can show the name of a hidden object. Dependency and pending-change counts include hidden objects, but never their names.
- **Rotating a resource signing key does not revoke IDs on the gateway that created the resource.** After a rotation, that gateway still accepts the old IDs of the App that created the resource. This also applies with a grace period of 0. Every other gateway refuses them, and every gateway refuses them for other Apps. To stop an App from using its resources, deactivate its key or the App.
- **Gemini 3 tool calls with several turns fail on `/ai/` and `/v1`.** Gemini refuses the second turn with `Function call is missing a thought_signature`. Use the native `/llm/` endpoint for these conversations.
- **Do not use `claude-haiku-4-5` as the LLM judge.** Its answers are cut off, so it gives no opinion on about a third of flags. The verdict of the filter then stays, which matters most in **Soften blocks** mode.
- **A Workspace-scoped Editor sees "missing permission" notices on some detail pages (Enterprise).** They show in the plugin, analytics, MCP connection, and tag sections. The forms that the role can use open and save.
- **Edge Gateways do not enforce scope approval.** An Edge Gateway gives a plugin the scopes that it declares, also while AI Studio shows the approval as pending. Review the declared scopes of a plugin before you change its command or upgrade it.
- **AI Studio does not show if an Edge Gateway reloaded a changed plugin.** An Edge Gateway shows **In sync** when it stores the pushed configuration. The reload comes after that, and can fail. Look for `Reloading changed plugin` and `Plugin could not be loaded` in the Edge Gateway log.
- **MCP call records have no retention pruning yet.**
- **The proxy log API does not return `service_tier` yet.**
- **MCP proxies created in Tyk Dashboard do not set `stripAuthorizationData`.** AI Studio-minted Tyk keys can reach third-party upstream services. Tyk Gateway connections set it.
- **Rate limiter concurrency slots can stay held for up to ten minutes** after a request that ends with no response.

<Accordion title='Added Agent Call Tracing (Enterprise)'>
AI Studio records what each agent does, from the traffic that the gateway already sees. You do not need an SDK or code changes in the agent.

- The **Agent sessions** page lists sessions, with filters. Each session has a transcript, a timeline, and a find bar. The timeline shows one labeled row for each step, with zoom and pan, and works for sessions with hundreds of turns.
- Tracing captures the `/llm/` and `/ai/` endpoints, Bedrock, Studio tools, MCP, data sources, and Edge Gateway plugin endpoints, on AI Studio and on Edge Gateways. It also records the decisions of the gateway, such as a filter or budget block, a failover, or a routing choice.
- AI Studio links each tool call to the LLM call that asked for it, with a confidence level. It infers the tools that an agent runs itself from its LLM traffic.
- Tracing is off until you set `AGENT_TRACING_ENABLED`. Content capture is a separate setting: `off`, `metadata`, `redacted`, or `full`. You set it globally, for each App, and for each request, under a ceiling that you control (`AGENT_TRACING_CONTENT_CEILING`). AI Studio always removes secrets and encrypts captured content at rest.
- Reading captured content needs the new `trace-content:read` permission, and AI Studio audits every read. Viewers, Editors, and Auditors see end users as stable pseudonyms.
- You can export a session as JSON or Markdown, purge sessions, and erase all data about an end user.
- You can export finished turns over OpenTelemetry (GenAI semantic conventions), with presets for Langfuse and Datadog LLM Observability.
- `AGENT_TRACING_BAGGAGE_ALLOWLIST` (default `session.id`, all editions) limits the W3C `baggage` header that AI Studio sends upstream to the listed keys.

In our tests, tracing stored about 8,000 spans per second on a 2-CPU PostgreSQL 16, from about 4 to 10 million stored spans.
</Accordion>

<Accordion title='Added guardrails for agent traffic (Enterprise)'>
Guardrails protect agents from indirect prompt injection in tool results, tool calls, and tool definitions.

- **Tool results are scanned.** Request guardrails inspect all tool results in the conversation history. This covers OpenAI, Anthropic (including server tools and MCP), Google, Bedrock, Ollama, the Responses API, each item of a batch, and the tools of Studio Chat.
- **Quarantine.** A blocked request stops an agent, because its next request carries the same tool result. The new `quarantine` action replaces only the flagged tool result with a placeholder, and the agent continues.
- **Tool calls are scanned (opt-in).** A guardrail checks the arguments of each tool call against the goal of the user. It refuses a dangerous call before the client runs it, also in a stream. In Studio Chat, a blocked call never runs.
- **Tool definitions are scanned (opt-in).** A guardrail can remove a poisoned tool description before the model sees it.
- **Shadow mode.** A guardrail logs what it would do, in the background, with no added latency.
- **Cost control.** Each node caches verdicts, so the history that an agent sends again on every turn is not classified again. Budgets for each request limit the cost of one request. Text over a budget is flagged as unscanned. The built-in pattern library is up to 16 times faster on prose.
- **Providers.** Lakera Guard, Azure AI Content Safety Prompt Shields, Azure AI Language PII, Presidio, Bedrock Guardrails, and HTTP classifiers all handle tool results. HTTP classifiers can also use a local Unix socket (`GUARDRAIL_UNIX_SOCKET_ALLOWLIST`).
- **A ready-made filter**, *Prompt injection in tool results (quarantine)*, is added. It is not attached.

When a guardrail blocks a request, the client now gets the reason, a stable reason code, and a request ID. The response never includes the matched text. In the console, each compliance event shows what happened, why, and how to fix it. You can optionally show an excerpt of the flagged text, with credentials and personal data masked. App owners can see the recent blocks of their own Apps in the AI Portal.

See [Guardrails](/ai-management/ai-studio/guardrails).
</Accordion>

<Accordion title='Added trusted prompt templates (Enterprise)'>
An App that wraps untrusted text (such as a pull request or an issue) in its own instructions can have that template approved. Request guardrails then score only the parts that change, so the instructions of the App are no longer flagged as injection.

- Matching is exact. Text that is not an approved, byte-for-byte match is scored whole. Tool results are never exempt.
- A backstop also scores the full message. It logs by default. For Apps whose text comes from untrusted authors, set it to enforce.
- Users propose templates on the App page. Only a full administrator approves them. The approval view shows the exact bytes of each constant, with hidden characters marked, and a diff against the previous version.
- Templates also apply on Edge Gateways.
- An HTTP classifier that handles templates itself, such as the Wolf Defender guardrail, uses `templates: "true"` on its connection.
- A constant at the start or end of a template can be as short as 16 bytes (`PROMPT_TEMPLATE_MIN_ANCHORED_CONST_BYTES`, 8 to 32).
</Accordion>

<Accordion title='Added guardrail exceptions and App guardrail capability (Enterprise)'>
You can fix a false positive for one App without changing the whole filter to log.

- In **Compliance → Filter Events**, select **Not a threat? Soften for this app** on a flagged event. The dialog uses the details of the event, and you choose what happens instead of the block, such as log.
- An exception changes the result of a verdict for one App, filter, detector, and channel. It never changes detection, and it is never based on the text. A second detector without an exception still blocks.
- An exception from a full administrator applies immediately. Other users who can edit the App propose an exception, and a full administrator approves it. App owners can select **Report false positive** on a blocked request in the AI Portal, which also proposes an exception.
- Exceptions expire after 30 days with no hit. Each hit is recorded on the compliance event. Edge Gateways apply exceptions after the next push.

A full administrator attests the guardrail capability of each App on the App page: **Read-only**, **Reads with tools**, or **Acting**. This capability limits how far an exception can soften a verdict. AI Studio suggests a capability from the tools, MCP servers, and data sources of the App. An App with no attestation counts as Acting, the strictest level. If a user who is not a full administrator changes these resources, AI Studio clears the attestation.
</Accordion>

<Accordion title='Added a second opinion from an LLM judge (Enterprise)'>
A guardrail can ask an LLM that you configure (the judge) if a flagged item is harmless for the App that sent it.

- **Record only.** The request keeps the verdict of the filter. The judge answers in the background, and **Filter Events** shows how often it disagreed.
- **Soften blocks.** A benign opinion changes a block to the softest action that the attested capability of the App allows.
- The judge is asked only about prompt-injection findings. It is never asked about secrets, personal data, moderation, denied topics, blocklists, or text that it cannot see in full. If the judge fails, the verdict stays.
- Judge calls go directly to the judge LLM and use its budget, with the interaction type `guardrail_judge` in analytics. The judge LLM must have a privacy score at least as high as the LLMs that the filter protects.
- Studio Chat is not judged.
</Accordion>

<Accordion title='Added guardrail alerts and outcome events (Enterprise)'>

- **Log and raise event.** A new guardrail action lets traffic through, in the same way as log, and raises an event named `guardrail.alert.<name>`. Webhooks can subscribe to it. It is available on the filter, for each tool channel, on exceptions, and in shadow mode. Alerts do not include the flagged text unless you opt in.

<Accordion title='Added FIPS 140-3 builds'>
AI Studio and the Edge Gateway are available as FIPS 140-3 compliant builds. They use the Go Cryptographic Module v1.0.0 ([CMVP certificate #5247](https://csrc.nist.gov/projects/cryptographic-module-validation-program/certificate/5247)). Standard builds do not change.

- **Packages** for both editions on amd64, arm64, and s390x: `tyk-ai-studio-fips`, `tyk-ai-studio-fips-ee`, `tyk-microgateway-fips`, and `tyk-microgateway-fips-ee`.
- **Images** `tykio/tyk-ai-studio-fips` and `tykio/tyk-microgateway-fips` (amd64 and arm64, Enterprise edition). They use the same paths, ports, and settings as the standard images.
- Both binaries log a `FIPS 140-3` line at startup and report `fips` from `GET /health`. Edge Gateways report their FIPS status to the Edge Gateways page.
- In FIPS mode, AI Studio stores passwords and secrets in approved formats. Every build reads both formats, so a database can move between standard and FIPS builds. A FIPS build encrypts existing secrets again in the background, and updates each password at the next login of the user.
- Plugins can be published as FIPS variants. AI Studio warns when it starts a plugin that is not a FIPS build.

Before you move a deployment to FIPS:

- Start once in FIPS mode and let the background encryption finish before you enforce strict mode (`GODEBUG=fips140=only`).
- Use FIPS builds of every plugin.
- FIPS mode allows only TLS 1.2 and 1.3 with approved ciphers and curves. Peers that offer only ChaCha20-Poly1305 or only plain X25519 cannot connect.
- Use RSA 2048 or larger, ECDSA P-256, P-384, or P-521, or Ed25519 for TLS certificates. Use RSA 2048 or larger or ECDSA for plugin-signing keys and SSO identity providers.
- Use SCRAM-SHA-256 authentication for PostgreSQL.
- Set a signing secret for every LLM. Resource IDs signed in standard mode from a short credential do not verify in FIPS mode.
</Accordion>

<Accordion title='Added several control planes for Edge Gateways'>
`CONTROL_ENDPOINTS` gives an Edge Gateway an ordered list of control planes, with its own region first.

- When its connection fails, the Edge Gateway tries the other control planes immediately. It backs off only when all of them fail.
- A configuration push in progress completes on the control plane that it arrives at. Keys created just before the failure validate through the other control plane.
- `EDGE_CONTROL_FAILBACK_INTERVAL` moves the Edge Gateway back to its first control plane when it is available again, with no dropped requests.
- The log, `/ready`, and the new `microgateway_control_connected` metric show the endpoint in use.

<Accordion title='Added Edge Gateway startup without a control plane'>
With `EDGE_START_FROM_LAST_KNOWN_GOOD=true`, an Edge Gateway that restarts while no control plane answers starts from the last configuration snapshot that it applied. It keeps this snapshot encrypted in its own database.

- The Edge Gateway reports `config_source: last_known_good` on `/ready` and in the `microgateway_config_source` metric. `microgateway_config_age_seconds` shows how long it has had no control plane.
- It takes the live configuration when it reconnects.
- `EDGE_STARTUP_CONTROL_TIMEOUT` (30 seconds) sets how long it tries the control planes first. `EDGE_LAST_KNOWN_GOOD_MAX_AGE` (72 hours) sets the maximum age of the snapshot.
- Without full credential sync, it cannot validate any key until a control plane answers. Every key gets `503 credential_check_unavailable`.
- It needs a database that survives the restart. With Helm, use `kind: StatefulSet` and `persistence.enabled`.

This setting is off by default.
</Accordion>

<Accordion title='Added full credential sync for Edge Gateways (Enterprise)'>
With `EDGE_CREDENTIAL_SYNC=full`, an Edge Gateway keeps a hashed list of the App keys of its namespace in its own database. It validates keys from this list when no control plane answers.

- The list contains a keyed hash of each key and its App. AI Studio sends a full list first and at least every 15 minutes, and only the changes in between. No key leaves AI Studio, and an Edge Gateway cannot get a key from a hash.
- The Edge Gateway syncs the list on each registration and heartbeat, and within about one second when a key on the list changes.
- While no control plane answers, it accepts a known active key and refuses a deactivated one, for up to `EDGE_CREDENTIAL_SYNC_MAX_AGE` (24 hours) after the last sync. A key created after the last sync gets `503`.
- New metrics: `microgateway_credential_sync_last_success_timestamp`, `microgateway_credentials_synced`, `microgateway_credential_validations_total{source}`, and `microgateway_credential_sync_calls_total{trigger}`.

With a Community or older AI Studio, the Edge Gateway validates keys on demand.
</Accordion>

<Accordion title='Added fast key revocation on Edge Gateways'>
When you create, regenerate, activate, deactivate, or delete a key, or activate or deactivate its App, AI Studio tells every connected Edge Gateway. The Edge Gateway removes the cached key, so a revoked key stops working within about one second. The event identifies the key only by its hash. Plugins cannot raise this event.
</Accordion>

<Accordion title='Added database failover handling for active-active deployments'>
AI Studio can run in two regions with one replicated PostgreSQL database.

- **Writes wait during a failover.** A request that arrives while the PostgreSQL primary is replaced waits for the new primary, up to `DATABASE_WRITE_RETRY_WINDOW` (15 seconds), and is applied once. If no primary takes over in time, AI Studio returns `503` with `Retry-After` and the code `database_unavailable`, and writes nothing.
- **Readiness reports the database state.** `/ready` reports `"database": "writable"`, `"read_only"`, or `"unreachable"`. It stays `200` during a failover shorter than `DATABASE_READY_GRACE` (30 seconds). `/ready?require=write` returns `200` only while the database takes writes. `/health` never checks the database.
- **Replicas reconnect to the new primary.** A replica on a demoted primary notices from the first refused write, or within 5 seconds when idle, and reconnects. Use a `DATABASE_URL` that names both hosts with `target_session_attrs=read-write`.
- **Startup waits for the database.** On PostgreSQL, AI Studio waits up to `DATABASE_STARTUP_TIMEOUT` (60 seconds) for a writable database. `DATABASE_STARTUP_TIMEOUT=0` keeps the old behavior.
- **New settings:** `CLUSTER_NODE_LABEL`, `DATABASE_MAX_OPEN_CONNS`, `DATABASE_MAX_IDLE_CONNS`, `DATABASE_CONN_MAX_LIFETIME`, and `DATABASE_CONNECT_TIMEOUT`.
- **New metrics:** `aistudio_db_writable`, `aistudio_db_failovers_total`, `aistudio_db_write_retries_total`, `aistudio_db_write_hold_seconds`, `aistudio_db_writes_held`, and `aistudio_db_unavailable_responses_total`.
</Accordion>

<Accordion title='Added Workspaces and service accounts'>

- **Workspaces (Enterprise).** Every configuration object belongs to a Workspace. You can assign a role within one Workspace to a user, a service account, or a team. The role then applies only to the objects of that Workspace. Model providers, tools, data sources, filters, embedders, secrets, file stores, and MCP servers stay readable from every Workspace. You change them only from their own Workspace. Apps, agents, routers, and catalogs outside your Workspaces are hidden. Manage Workspaces in **Access > Workspaces**. ##### Security Fixes

<AccordionGroup>

<Accordion title='Fixed unauthenticated admin access to the Edge Gateway API'>
We have resolved an issue where `POST /api/v1/auth/token` issued admin tokens to anyone who could reach the HTTP port of an Edge Gateway. With such a token, an attacker could load a malicious plugin and read or change all traffic. The route is removed, and Edge Gateways no longer serve `/api/v1`. This was also fixed in 2.2.2.

On a standalone Edge Gateway, create tokens with `POST /api/v1/tokens` or `microgateway -create-admin-token`. On an Edge Gateway (`GATEWAY_MODE=edge`), `-create-admin-token` now fails with a clear error.
</Accordion>

<Accordion title='Fixed submitted assets reaching internal services'>
The internal-address block now covers outbound calls for LLMs, Studio Chat, embedders, tools, data sources, vector stores, guardrail providers, plugin registries, and the MCP wizard. Before this release, a submitted tool or data source could probe internal services. Each asset has an **Allow internal host** switch that only administrators can set. AI Portal submissions cannot set it. Plugin hosts are now classified by their parsed address.
</Accordion>

<Accordion title='Fixed LLM credentials and App keys stored in plain text'>

- AI Studio encrypts LLM API keys and credential fields (such as the AWS keys of Bedrock) with `TYK_AI_SECRET_KEY`. They are no longer copied in plain text into events, object hooks, SQL logs, or the Edge Gateway database.
- AI Studio stores the App gateway key encrypted with AES-256-GCM, and finds it by a keyed hash. The encryption key comes from `TYK_AI_SECRET_KEY` and a salt for each database. A copy of the database, such as a backup or the replica in a second region, no longer holds usable keys. AI Studio still shows the key in the same places.
- Edge Gateways with full credential sync hold only keyed hashes (HMAC-SHA-256) of App keys. The cache of validated App keys on an Edge Gateway also holds hashes.
- Standalone Edge Gateways store a keyed hash of each API token.
- SQL logs no longer contain values unless you set `DB_LOG_SQL_PARAMS=true`.
</Accordion>

<Accordion title='Fixed credentials exposed in events, hooks, and API responses'>

- System events and object hooks now show these values as `[redacted]`: tool auth keys, data source connection strings, user password hashes and tokens, App gateway keys, and guardrail secrets.
- The API no longer returns guardrail provider keys. Literal secret connection fields, such as the `api_key` of Lakera, Azure, and HTTP providers, and the Bedrock `secret_access_key`, read `[redacted]` for every role. Saving with `[redacted]` keeps the stored key.
- Guardrail provider credentials reach Edge Gateways encrypted.
- Guardrail error events no longer include the error message of the provider, which could contain the screened text.
- Secret plugin configuration fields were masked only in the edit form. Examples are the Redis password of rate-limiter and the `vault_token` of github-rag-ingest. The plugin detail page, the plugin API, and the plugin UI registries showed them to every user who could read plugins. Every field that the plugin schema marks `format: password` or `writeOnly` now reads `[redacted]`. This applies to the API, agent and model provider responses, and `system.plugin.*` events. If you save a form without typing the secret again, AI Studio keeps it.
</Accordion>

<Accordion title='Fixed marketplace URLs reaching internal services'>
Before this release, the check of a marketplace URL (`POST /api/v1/admin/marketplaces/validate`) needed only `marketplace:read`, which the Viewer and Auditor roles have. AI Studio also fetched marketplace indexes without the internal-address block. A read-only user could make AI Studio call internal addresses, and find out from the error what answered. The check now needs `marketplace:write`. Marketplace fetches refuse internal addresses, names that resolve to them, and redirects to them. A failed fetch gives one error for every cause, and AI Studio logs the cause.
</Accordion>

<Accordion title='Fixed API keys readable by users who can view users'>
Before this release, listing or reading users returned the full API key of each user to anyone with permission to read users. A role that only views users was able to take over any account, including administrator accounts. AI Studio now shows a key in full only once, when it is issued or rolled. After that, the console and the API show only its last four characters.
</Accordion>

<Accordion title='Fixed data source passwords visible to readers'>
A password in a data source connection string, such as `postgres://user:password@host/db`, was shown to everyone with permission to read data sources. It now reads `[redacted]`. References such as `$SECRET/` and `$ENV/` are still shown.
</Accordion>

<Accordion title='Fixed credentials exposed in chat and AI Portal agent responses'>

- Starting a chat sent the full records of its tools and data sources to the browser. These included vector store API keys, connection strings, and tool auth keys. Chat now receives only their names and descriptions.
- The AI Portal agent list returned the configuration of each agent, its plugin, and its App. Everyone with access to the agent saw them. It now returns only the details of the agent, with the plugin and App as IDs.
</Accordion>

<Accordion title='Fixed requests bypassing plugins that failed to load'>
If one pre-auth or post-auth plugin of an LLM did not load on an Edge Gateway, the Edge Gateway skipped all plugins of that LLM. It then sent the request to the vendor. As a result, a second, broken plugin let requests bypass a firewall or rate limiter plugin. The Edge Gateway now refuses the request with `503` (`plugin_load_failed`) until the plugin loads.
</Accordion>

<Accordion title='Fixed credential references resolving any environment variable'>

- `$ENV/` references resolve only for names in `AI_STUDIO_ENV_REF_ALLOWLIST`.
- Changing a credential reference needs the `secrets:read` permission.
- Vendor clients no longer read keys or endpoints from environment variables.
- A credential that points to an empty secret no longer reaches Edge Gateways as an empty key. Before this release, a client could fill an empty key from the environment of the Edge Gateway.
</Accordion>

<Accordion title='Fixed plugins running with more access than they need'>

- `AI_STUDIO_PLUGIN_ALLOWED_SOURCES` and `PLUGINS_ALLOWED_SOURCES` restrict the plugin deployment types (`oci`, `file`, and `grpc`) that AI Studio and each Edge Gateway accept.
- Plugins run with an explicit environment, can call only the service APIs whose scopes an administrator approved, and can change only their own configuration.
- AI Studio verifies plugin signatures in-process (Enterprise), with no external `cosign` binary, so verification also works in the distroless images. It accepts cosign v2 and v3 signature formats, and checks transparency-log entries.
- AI Studio checks cached plugin binaries against their original hash before it loads them.
</Accordion>

<Accordion title='Fixed requests that filters and vendors could read differently'>
AI Studio now refuses requests with duplicate JSON keys, keys that differ only in case, ambiguous multipart uploads, and alternative path spellings. Before this release, a filter could screen one prompt while the vendor received another. When request filters are attached, AI Studio no longer passes prompts that filters cannot read.
</Accordion>

<Accordion title='Fixed Apps reaching the OpenAI resources of other Apps'>
One App can no longer use the OpenAI responses, conversations, or batches of another App. AI Studio ties each ID to the App that created it.
</Accordion>

<Accordion title='Fixed data leaks through images in chat responses'>
A prompt injection could make the browser of the user send data to any address through an image URL. Chat no longer loads images from model responses by default. Turn on **Render images in responses** for chats that need images.
</Accordion>

<Accordion title='Fixed unauthenticated access to the SSO nonce endpoint'>
The SSO nonce endpoint now requires the shared secret of the identity broker. SSO nonce tokens now use a cryptographically secure random source.
</Accordion>

<Accordion title='Other security fixes'>

- `pdftotext` runs only from the `PATH`, with a minimal environment.

</Accordion>

### 2.2.1 Release Notes

#### Release Date 2 October 2026

#### Release Highlights

Tyk AI Studio 2.2.1 is a patch release. It extends authentication plugins to every gateway endpoint and records who made a delegated call. It also fixes several issues with the connection between AI Studio and Edge Gateways. Read the Breaking Changes section below before you upgrade.


#### Breaking Changes

- **Authentication plugins now protect more endpoints, so App keys stop working there.** On Edge Gateways, the authentication plugins of an LLM now also run on `/ai`, `/v1`, `/anthropic`, and `/router`, not only on `/llm/`. On these endpoints, an LLM with an authentication plugin no longer accepts App keys. Give these clients tokens that the plugin accepts, or remove the plugin from the LLM. A rejected request now returns `401 invalid credential`, not `500` with the reason of the plugin. AI Studio also refuses a plugin result without an App ID. The embedded gateway in AI Studio does not run authentication plugins, and still accepts App keys.
- **The push API and the Community Edition edge detail API changed.** A push now ends as `succeeded`, `succeeded_with_warnings`, `partially_failed`, `failed`, or `expired`. The `completed` and `timed_out` states are removed, so update scripts that wait for `completed`. A push with no Edge Gateway to send to returns `409`. In the Community Edition, `GET /api/v1/edges/{edge_id}` now wraps its response in `{"data": …}`, as in Enterprise.
- **The connection between AI Studio and Edge Gateways is stricter.** Edge Gateways require TLS 1.2 or later. AI Studio limits gRPC messages to 16 MB. If you increased `GRPC_MAX_MESSAGE_SIZE` on an Edge Gateway, set the same value on AI Studio. Edge Gateways now load `EDGE_TLS_CA_PATH`. The file replaces the system root certificates, so it must contain the issuer of the AI Studio certificate.
- **For plugin and SDK developers:** The enterprise module path is now `github.com/TykTechnologies/ai-studio-enterprise/v2`. The gateway plugin interfaces moved to `pkg/gatewayplugin`. The old `microgateway/plugins` paths forward to it. The Go `StudioServices` interface has thirteen new methods, so custom fakes must add them. Built plugins continue to work.


#### Upgrade Instructions

- **Database changes are automatic, and you can roll back.** The schema moves to version 6. A 2.2.0 binary still runs on a 2.2.1 database.
- **Upgrade AI Studio and your Edge Gateways together.** Edge Gateways apply the new authentication plugin lists after the next configuration push.
- **Helm upgrades briefly stop AI Studio.** The AI Studio Deployment now uses the `Recreate` strategy. During the upgrade, Edge Gateways continue to serve traffic.

### 2.2.0 Release Notes

#### Release Date 29 September 2026

#### Release Highlights

Tyk AI Studio 2.2.0 is the largest release on the 2.x line. You can now reach every LLM in an App through one OpenAI-compatible URL, keep traffic flowing when a provider goes down, and govern tool calls in the same way you govern prompts. This release also includes a large set of security fixes. Read the [Breaking Changes](#breaking-changes) section before you upgrade.

**One endpoint for every model**

Apps can now call `POST /v1/chat/completions` with a model name in the form `{llm-slug}/{model}`, for example `openai/gpt-4o` or `bedrock/claude-sonnet`. One URL and one App credential reach every LLM the App has access to, whatever the upstream vendor. `GET /v1/models` lists the models the caller can use.

There is also a native Anthropic Messages endpoint for Bedrock (`/anthropic/{slug}/v1/messages`). Point Claude Code at it with `ANTHROPIC_BASE_URL` and it runs against Claude models on AWS Bedrock, with AI Studio authentication, budgets, filters, and analytics applied to every request.

**LLM failover**

Each LLM configuration can now have an ordered list of fallback LLMs and models. When the primary provider returns a 5xx, 408, or 429 error, times out, or refuses the connection, AI Studio tries the next fallback in the list. Every attempt goes through the same authentication, budget, and filter checks. Failover is available in the Community and Enterprise editions.

**Filters on tool calls, and guardrails without scripts**

Filters attached to a [tool](/ai-management/ai-studio/tools) now run in both directions (arguments in, response out) over REST, all MCP transports, and chat, on AI Studio and on Edge Gateways. If a tool filter fails, it blocks the call.

Enterprise adds a second kind of [filter](/ai-management/ai-studio/filters): [guardrails](/ai-management/ai-studio/guardrails). A guardrail uses a detection provider instead of a script, and then blocks, redacts, or logs the content. You can use the built-in pattern library for credentials, personal data, and prompt-injection heuristics, or connect to Lakera, Microsoft Presidio, Azure AI Content Safety, Azure AI Language PII, Amazon Bedrock Guardrails, or your own HTTP classifier. Each guardrail hit records a compliance event. The event does not contain the matched text. New Enterprise installations include four default guardrails. They are not attached, so nothing is enforced until you attach them.

**Enterprise governance: roles, audit, metadata, and webhooks**

- **[Fine-grained RBAC](/ai-management/ai-studio/rbac)** replaces the old admin or non-admin model. It has permissions for each resource and action, five system roles (Owner, Administrator, Editor, Viewer, Auditor), custom roles that you can clone, and role assignment to users and teams. A separate `publish` permission lets you give one person permission to edit a resource and another person permission to make it live.
- **[Audit trail](/ai-management/ai-studio/audit-trail)** records every change made through the management API, and every login, logout, failed login, and SSO event. Each record shows who made the change, when, from which IP address, and which fields changed. Secrets are redacted. You can filter the records in the console and export them to CSV or JSON. The audit trail is on by default.
- **[Governed metadata](/ai-management/ai-studio/governed-metadata)** lets administrators define required fields, such as owner, lifecycle state, risk tier, and data classification, for LLMs, tools, data sources, and plugin resources. A schema can be advisory or enforced. A coverage report shows which fields are missing, invalid, or expired.
- **[Outbound webhooks](/ai-management/ai-studio/webhooks)** send internal events as signed JSON to HTTP endpoints that an administrator has approved. Failed deliveries are retried with backoff and then moved to a dead-letter queue. If someone changes a webhook URL or its headers, an administrator must approve it again.

**Routing and cost control**

[Model Routers](/ai-management/ai-studio/model-router) are now governed assets. You publish them in LLM catalogs and grant them to Apps in the same way as LLMs. Apps call them on the unified endpoint as `{router}/{model}`.

Enterprise adds three more features:

- **[Semantic Routers](/ai-management/ai-studio/semantic-router)** choose a model based on the meaning of the prompt. A client sends `smart/auto`, and the router checks explicit routes, keywords, and similarity to example prompts. It can also ask an LLM to decide. If it cannot classify the prompt, it uses the default route. Shadow mode lets you test a router against live traffic before it changes anything.
- **Team budgets** set a monthly spending limit for all the Apps in a team. New Apps take their budget from the team's pool.
- **[Semantic caching](/ai-management/ai-studio/semantic-caching)** in the Advanced LLM Cache plugin (1.2.0) can answer a reworded prompt from the cache. Cache entries are never shared across Apps, models, or system prompts. Semantic caching is off by default.

**Import MCP Proxies from Tyk Dashboard (Enterprise)**

AI Studio can now [import MCP proxies](/ai-management/ai-studio/tyk-mcp-integration) that a Tyk Dashboard manages and publish them in the AI Portal. Developers bind these MCP servers to their Apps. For MCP proxies that use API keys, AI Studio creates a Tyk key for each App from policies that an administrator selects. Administrators can also register new MCP proxies from AI Studio. The Tyk Gateway continues to handle all MCP traffic.

**A new chat experience**

The [chat interface](/ai-management/ai-studio/chat-interface) is rebuilt. It streams one turn at a time, and you can cancel, edit a previous message, or regenerate a reply. **Client tools** let the model ask the person in the chat for approval or for information through a form. **Generative UI** lets the model show dashboards, tables, charts, and forms in the chat. The new interface is on by default. To use the previous interface, set `CHAT_UI_V2_ENABLED=false`.

**A faster Edge Gateway**

On our AWS benchmark, a 4-vCPU Edge Gateway with the full policy set now sustains about 9,000 requests per second. Before this release, it started at about 1,190 requests per second and dropped to about 640 within twenty minutes. Gateway overhead at p50 is less than 1 ms. When the gateway is close to its memory limit, it now rejects new requests with a `503` error instead of running out of memory.

**Admin console and AI Portal improvements**

Before you delete an object, AI Studio now shows what uses it. Every form warns you about unsaved changes. Lists are searchable and sortable and support bulk actions. [Privacy levels](/ai-management/ai-studio/privacy-levels) have names. Every detail page has a "Used by" section, and [notifications](/ai-management/ai-studio/notifications) now appear in the console. The AI Portal has a new Overview page, a single Browse catalog, and a detail page for each asset.

#### Breaking Changes

This release changes some default behavior, API responses, and status codes. Most upgrades need no action, but check each item below against your deployment.

- **A budget of `0` now means zero spend.** To set no limit, use `null` or leave the field empty. On first start, AI Studio changes existing App and LLM budgets of `0` to `null`, so no App is blocked.
- **`/metrics` is not served by default.** Set `METRICS_AUTH_TOKEN` and scrape with `Authorization: Bearer <token>`, or set `METRICS_ALLOW_UNAUTHENTICATED=true`. Until you set one of these, Prometheus scrape jobs get a 404 response.
- **App grants apply to every authentication method.** A request that uses an App's Bearer secret, a custom-auth plugin, or a gateway auth plugin gets a `403` response if the App is not granted the LLM or data source. An unknown LLM slug on `/v1` or `/ai/` now returns `403` instead of `404`.
- **New tools are chat-only by default.** REST and MCP access are now separate settings on each tool. A tool created after the upgrade returns `403` on `/tools/{slug}` and `/tools/{slug}/mcp` until you enable `rest_access_enabled` or `mcp_access_enabled`. Existing tools keep both access methods on. The REST endpoint also now rejects an `operation_id` that is not in the tool's operation list.
- **Tool filter direction is now respected.** Before this release, every filter on a tool ran on the tool's response. A filter that is not marked as a response filter now runs on the tool's input. The gateway logs a warning the first time each affected filter runs.
- **Filter scripts cannot use Tengo's `os` module.** Set `FILTER_SCRIPT_ALLOW_OS=true` if a script needs it. Scripts are also stopped after `FILTER_SCRIPT_TIMEOUT` (default `5s`) or `FILTER_SCRIPT_MAX_ALLOCS`, and when the caller disconnects. When a request filter is stopped, the request is blocked. HTTP requests from scripts are limited in size and time, and must go to hosts that `LLM_UPSTREAM_ALLOWED_HOSTS` allows, when it is set.
- **Enterprise no longer adds new LLMs, tools, or data sources to the Default catalog.** Add them to a catalog before teams can see them. The Community edition still adds them automatically. In both editions, approved submissions are created inactive and added to the Default catalog, and an administrator activates them.
- **[Custom roles](/ai-management/ai-studio/rbac) need the new `publish` permission to activate resources.** System roles are updated automatically. Custom roles are not changed. For example, a custom role with `llms:write` must also get `llms:publish` to activate LLM providers.
- **SSO users cannot get personal API keys by default.** Set `ALLOW_SSO_USER_API_KEYS=true` to allow this. An existing key for an SSO user stops working when the user's last SSO login is older than `SSO_API_KEY_LIVENESS` (default `720h`).
- **Some status codes changed.** Upstream connection failures return `502` or `504` instead of `500`. An Edge Gateway that cannot reach AI Studio to check a credential returns `503` with `Retry-After` instead of `401`. A budget check that cannot run returns `503`. On `/ai/` and `/v1`, budget refusals use the OpenAI error format with `code: budget_exceeded`. Update alerts and client retry logic that depend on the old codes.
- **The Edge Gateway's built-in rate limit settings are removed.** `ENABLE_RATE_LIMITING`, `GATEWAY_DEFAULT_RATE_LIMIT`, and the `mgw --rate-limit` flags never had any effect. Use a rate limiting plugin instead.
- **Importing tools from a Tyk Dashboard is now Enterprise only.** The import uses a saved [Tyk connection](/ai-management/ai-studio/tyk-mcp-integration), and the `/api/v1/providers/*` routes are removed.
- **`/login-sso-profile` returns less data.** It returns only `profile_id`, `name`, the provider type, and `login_url`.
- **Data sources use [Embedders](/ai-management/ai-studio/embedders).** API clients that create data sources should send `embedder_id` instead of inline embedding settings.
- **Some API responses changed.** `/common/me` has new fields, such as `permissions`, `roles`, `auth_source`, and `has_api_key`. `GET /common/api/v1/notifications` returns `{data, meta}` and accepts `limit`, `offset`, and `unread`. Users without `users:write` see other users' API keys masked, with `api_key_hint` and `has_api_key` instead. `PATCH /users/:id` no longer changes `is_admin` when you leave it out.
- **The API validates more input.** List endpoints return `400` for an unknown `sort` field (use `-name` for descending order). A `privacy_score` outside 0 to 100 returns `400`. `POST /<type>/bulk` accepts up to 100 IDs. An explicit `team_id` on App create or update must be one of the owner's teams, unless the caller has `groups:write`.
- **For plugin and SDK developers:** `aigateway.Gateway` has two new methods, `UnifiedRouterBasePath()` and `SetRouteResolver()`, and `sso.Service.HandleSSO` now takes a `*NonceTokenRequest`. New App bindings to plugin resources that an App cannot unlock are refused with `400`. You must build with Go 1.26.6. Plugin modules that use a `replace` directive must update their `go` directive.

#### Upgrade Instructions

- **Database changes are automatic.** The schema updates on first startup. The first startup also runs some one-time tasks: it encrypts stored secrets again in the new format in the background, moves inline embedding settings to Embedders, and assigns existing Apps and spend to teams.
- **Upgrade AI Studio and your Edge Gateways together.** Older Edge Gateways ignore new configuration fields. They cannot serve Semantic Routers, enforce zero budgets or team budget blocks, or turn off a tool's REST or MCP access.
- **Package-installed Edge Gateways need one manual change.** A package upgrade keeps your existing `/etc/default/tyk-microgateway` file. If the Edge Gateway was installed before 2.2, add `PLUGINS_CONFIG_PATH=/opt/tyk-microgateway/config/analytics-pulse-config.yaml` to that file. If you do not, AI Studio receives no analytics or spend data from that Edge Gateway. New package installations load the analytics pulse by default.
- **Enterprise: RBAC roles are created on first startup.** User ID 1 becomes Owner, and every other admin user becomes Administrator.
- **Check your Model Routers before you upgrade.** AI Studio now rejects a Model Router slug that is the same as an LLM slug. In earlier versions, the LLM always took priority, so such a router could not be reached. Also grant each Model Router to the Apps that use it. An App that calls a router it is not granted is still served, but only from the LLMs granted to the App directly. This fallback is deprecated.
- **Edge Gateway analytics are now deleted after a retention period.** The default is 7 days when the analytics pulse is on, and 90 days otherwise. After the upgrade, the first cleanup deletes older rows in small batches. Set `ANALYTICS_RETENTION_DAYS` to keep them longer.
- **Edge Gateway SQLite databases now use WAL mode.** Make sure the database directory is writable, because SQLite creates `-wal` and `-shm` files next to the database.
- **Count requests with `failover_attempt = 0`.** Each failover attempt is now its own row in `proxy_logs`.

<Accordion title='Added guardrail filters (Enterprise)'>

Providers are a built-in pattern library, which runs with no network calls and validates matches such as payment card numbers and IBANs, and connectors for Lakera, Microsoft Presidio, Azure AI Content Safety, Azure AI Language PII, Amazon Bedrock Guardrails, and a generic HTTP classifier.

<Accordion title='Fixed response format issues with LLM vendors'>
We have resolved several issues where AI Studio returned responses that did not match the OpenAI format, or recorded the wrong usage:

- **Amazon Bedrock:** Tool call arguments were always empty, and streamed responses did not include tool calls.
- **Anthropic:** A reply that contained text and a tool call was split into two choices, and its token usage was counted twice. Streamed responses also counted too many output tokens. An empty reply returned a `502` error instead of a successful response.
- **Google Gemini:** Some responses could not be decoded, so their analytics records were lost. Tool calls were returned without an ID.
- **All vendors:** A request with `stream: true` and tools returned a buffered response. Error responses did not follow the OpenAI error format, and some upstream 4xx errors were returned as 5xx errors.

Responses now match the OpenAI format for every vendor, and usage and cost are recorded correctly.
</Accordion>

<Accordion title='Fixed request parameters being dropped or changed'>
We have resolved several issues where AI Studio did not send the client's request parameters to the vendor as expected:

- `max_tokens` was ignored on the Main Ingress and `/ai/`. OpenAI upstreams got no limit, and Anthropic and Bedrock got a limit of 2048 tokens.
- `reasoning_effort` was not sent to the vendor through the Main Ingress or `/ai/`.
- `/ai/` always used the LLM's default model instead of the `model` in the request. This also overrode the model mappings of Model Routers.
- Anthropic requests included `temperature: 0` when the caller did not set a temperature, so models that no longer accept this parameter, such as `claude-sonnet-5`, returned `400`.
- OpenAI requests required `stream_options.include_usage`, so models that reject this parameter could not be called with clients such as the Vercel AI SDK.
- `X-Cache` headers from the cache plugin were not returned on the Main Ingress and `/ai/`.

AI Studio now passes these parameters and headers through correctly.
</Accordion>

<Accordion title='Fixed Edge Gateways not reconnecting after an AI Studio restart'>
We have resolved an issue where Edge Gateways did not reconnect after AI Studio was unavailable for more than about five seconds. After a restart, Edge Gateways also ignored budget syncs and stopped sending analytics. Edge Gateways now reconnect, accept budget syncs, and send analytics after every AI Studio restart.
</Accordion>

<Accordion title='Fixed analytics lost during Edge Gateway shutdown'>
We have resolved an issue where a graceful Edge Gateway shutdown lost up to one pulse interval of analytics. The Edge Gateway now finishes open requests and sends its buffered analytics before it disconnects.
</Accordion>

<Accordion title='Fixed Edge Gateways serving outdated configuration after a push'>
We have resolved an issue where an Edge Gateway could keep serving old LLMs after a configuration push. The **Config Sync** status could also stay on Pending after a successful push. Every push now reloads the gateway, and the status updates when the Edge Gateway receives the configuration.
</Accordion>

<Accordion title='Fixed Edge Gateways with PostgreSQL failing to sync'>
We have resolved an issue where an Edge Gateway that used PostgreSQL could not sync after it had stored any analytics or budget data, and then refused every App with `403`. Edge Gateways now update Apps and LLMs in place during a sync.
</Accordion>

<Accordion title='Fixed post-auth plugins not running for LLMs with punctuation in their names'>
We have resolved an issue where post-auth plugins, such as caching and rate limiting, did not run on Edge Gateways for LLMs whose names contained punctuation, for example `Mock GPT (host)`. Model Routers that used these LLMs returned `404`. Edge Gateways now use the correct LLM slug after the next configuration push.
</Accordion>

<Accordion title='Fixed Anthropic requests returning 404 through the unified endpoint'>
We have resolved an issue where Anthropic requests returned `404` through the unified endpoint and `/ai/`, and where endpoints that already included `/v1` had it added again. AI Studio now joins the vendor URL and request path correctly, so an Anthropic endpoint works with or without `/v1`.
</Accordion>

<Accordion title='Fixed strict HTTP/2 clients failing on gateway responses'>
We have resolved an issue where the gateway sent a `Keep-Alive` header on HTTP/2 responses, which caused strict clients such as curl 8.10 and later to fail. The header is now sent on HTTP/1 only.
</Accordion>

<Accordion title='Fixed OpenAI-compatible endpoints on a TLS Edge Gateway'>
We have resolved an issue where every request to `/v1/chat/completions` or `/ai/` failed on an Edge Gateway with `TLS_ENABLED=true`. These requests now work on TLS Edge Gateways.
</Accordion>

<Accordion title='Fixed budget alerts and limits for Edge Gateway traffic'>
We have resolved an issue where traffic through Edge Gateways did not trigger App, LLM, or team budget alerts. Each budget sync now checks the Apps whose spend changed. A configuration push also no longer lowers an App's recorded spend, which could reopen a spent budget.
</Accordion>

<Accordion title='Fixed Apps exceeding their budget on the embedded gateway (Enterprise)'>
We have resolved an issue where the embedded gateway could let an App spend more than its budget for up to five minutes, because spend was cached. The cost of each request is now added as soon as it is recorded. Resetting an App budget now also clears the embedded gateway's cached spend.
</Accordion>

<Accordion title='Fixed missing reason in budget and filter errors'>
We have resolved an issue where budget refusals and filter blocks on `/ai/` and `/v1` did not include the reason, or wrapped the error message twice. These errors now include the reason. See [Breaking Changes](#breaking-changes) for the new error format.
</Accordion>

<Accordion title='Fixed PATCH requests removing an App budget limit'>
We have resolved an issue where `PATCH /api/v1/apps/:id` without `monthly_budget` removed the App's budget limit. An omitted field now keeps the stored value.
</Accordion>

<Accordion title='Fixed PATCH requests clearing LLM fields'>
We have resolved an issue where `PATCH /api/v1/llms/:id` cleared every field that the request did not include, such as the name, endpoint, and API key. PATCH now changes only the fields that you send.
</Accordion>

<Accordion title='Fixed filter order on LLMs not being respected'>
We have resolved an issue where filters on an LLM ran in database order, not in the order shown in the LLM form. You can now reorder filters, and they run from top to bottom. The first filter that blocks the request stops it.
</Accordion>

<Accordion title='Fixed MCP tool responses and schemas'>
We have resolved several issues with tools served over MCP:

- `tools/call` returned Go map text instead of JSON.
- The tool `inputSchema` did not mark required parameters, and ignored descriptions written on OpenAPI parameters.
- Every operation was marked as destructive. Annotations now depend on the HTTP method, and you can override them for each operation.
</Accordion>

<Accordion title='Fixed Edge Gateway MCP cache not refreshing'>
We have resolved an issue where the Edge Gateway's MCP cache was never cleared. If you deleted a tool and created it again with the same name, the Edge Gateway could not find it until it restarted. The cache now refreshes when a tool changes.
</Accordion>

<Accordion title='Fixed browser MCP clients failing to connect'>
We have resolved an issue where browser-based MCP clients could not connect to the tool and MCP endpoints because CORS headers were missing. Both gateways now send CORS headers on these endpoints.
</Accordion>

<Accordion title='Fixed missing tool analytics for Edge Gateway traffic'>
We have resolved an issue where tool calls served by Edge Gateways did not appear in a tool's analytics. Each tool call is now sent to AI Studio and recorded with the same detail as calls served by AI Studio.
</Accordion>

<Accordion title='Fixed Edge Gateway request body storage settings being ignored'>
We have resolved an issue where Edge Gateways stored request and response bodies even when `ANALYTICS_STORE_REQUESTS` and `ANALYTICS_STORE_RESPONSES` were off. Edge Gateways now respect these settings.

<Accordion title='Fixed incomplete Edge Gateway analytics'>

<Accordion title='Fixed the Compliance dashboard failing on SQLite (Enterprise)'>

<Accordion title='Fixed OCI plugin installs and large plugin downloads'>

<Accordion title='Fixed plugin data remaining after plugin deletion'>

<Accordion title='Fixed wrong cached answers in Advanced LLM Cache (Enterprise plugin)'>

This affected all Gemini requests, and some OpenAI and Anthropic requests. Streamed cache hits on Edge Gateways also came back empty, and updating a hit count could bring back a deleted entry. ## 2.1 Release Notes

### 2.1.0 Release Notes

#### Release Date 14 May 2026

#### Release Highlights

Tyk AI Studio 2.1.0 is the first feature release on the 2.x line. It expands the range of AI providers you can manage, gives compliance teams visibility into what your guardrails are actually doing, and makes the platform easier to monitor and extend.

**AWS Bedrock support**

You can now connect [AWS Bedrock](/ai-management/ai-studio/llm-management) as an LLM provider, alongside OpenAI, Anthropic, and the other supported vendors. Bedrock works everywhere the other vendors do: in the chat interface, through the OpenAI-compatible API, with full streaming, and on Edge Gateways. Applications already built with the AWS SDK can call Bedrock through Tyk without any code changes, so you get governance, budgets, and analytics on top of your existing integration. The LLM setup form guides you through entering AWS credentials, which can be stored encrypted using AI Studio's secrets manager.

**See what your guardrails are doing with Compliance Events**

Until now, the Compliance dashboard could only show you requests that were blocked outright. In practice, most governance activity is quieter than that: a filter redacts an email address, rewrites a risky passage, or flags something suspicious while letting the request through. Those interventions were invisible.

With [Compliance Events](/ai-management/ai-studio/compliance-events), your content filters can record exactly what they did and why. The events appear in a new Filter Events tab on the Compliance dashboard, where you can filter by severity, drill into the details, follow trends over time, and export everything to CSV for audits. Events recorded on Edge Gateways flow back to the central dashboard automatically. See [Filters](/ai-management/ai-studio/filters#compliance-event-reporting) to get started.

**Monitor AI Studio with your existing tools**

AI Studio and the Edge Gateway now publish [operational metrics](/ai-management/ai-studio/analytics#prometheus-and-opentelemetry-metrics) that Prometheus, Grafana, and OpenTelemetry-based tools can scrape out of the box: request volumes, token usage, cost, tool calls, policy blocks, and latency. Monitoring is on by default, so most teams just need to point their existing dashboards at it.

**Keep sensitive conversations out of your logs**

A new per-LLM setting, **Disable Request/Response Body Logging**, stops the content of requests and responses from being stored in logs and analytics for that provider. Usage counts, costs, and performance data are still recorded. This is designed for teams handling regulated or sensitive data who need usage visibility without retaining the conversations themselves.

**New plugins**

Enterprise customers get a new OAuth2 plugin that connects AI Studio to identity providers such as Auth0, Microsoft Entra ID, and Okta, automatically setting up access for new applications based on the permissions defined in your identity provider. The community plugin collection adds a flexible rate limiter for LLM traffic and a plugin that keeps model pricing up to date automatically.

#### Breaking Changes

**Custom analytics handlers need a small update.** This only affects you if your team has written a custom analytics handler plugin. The handler interface changed in this release, so custom implementations need their method signatures updated before upgrading. The details are in the [Plugin SDK Reference](/ai-management/ai-studio/plugins/sdk). If you only use the built-in analytics, no action is needed.

#### Upgrade Instructions

- **Database changes are automatic.** The schema updates itself on first startup after the upgrade; there is no manual migration step. One side effect: analytics recorded before the upgrade cannot be attributed to a specific LLM configuration, so older traffic will not appear in the new per-LLM detail views.

<Accordion title='AWS Bedrock as an LLM provider'>
We have added AWS Bedrock as a fully supported LLM vendor. Bedrock models work through the chat interface, the OpenAI-compatible API, and streaming connections, on both the embedded gateway and Edge Gateways. Applications built directly on the AWS SDK can point at Tyk and keep working unchanged, gaining authentication, budgets, and analytics on the way through. <Accordion title='Compliance Events'>
Content filters can now record structured events describing what they did: PII redacted, content rewritten, a policy matched, or an error quietly handled. Each event carries a severity (info, warning, or critical) and supporting detail.

The Compliance dashboard surfaces these events with new summary cards for critical and warning activity, a clearer split between requests that were blocked and requests that were flagged but allowed through, risk scores that account for event severity, and a dedicated Filter Events tab with filtering, trends, and CSV export. Events from Edge Gateways are collected centrally and appear alongside everything else.

The filter scripts that ship with AI Studio (PII redaction, content blocking, response guardrails) have been updated to record these events out of the box. See [Compliance Events](/ai-management/ai-studio/compliance-events).
</Accordion>

<Accordion title='Operational metrics for Prometheus and OpenTelemetry'>
AI Studio and the Edge Gateway now expose a standard metrics endpoint covering request counts, token usage, cost, tool calls, policy blocks, latency, and in-flight requests. It works with Prometheus, Grafana, and any OpenTelemetry-based monitoring stack, and is enabled by default. See [Analytics & Monitoring](/ai-management/ai-studio/analytics#prometheus-and-opentelemetry-metrics) for the full list of metrics and configuration options.
</Accordion>

<Accordion title='Per-LLM control over body logging'>
A new **Disable Request/Response Body Logging** option on each LLM keeps the content of requests and responses out of logs and analytics for that provider, while still recording usage, cost, and performance data. It applies on both the embedded gateway and Edge Gateways, and is switched off by default so existing behavior is unchanged.
</Accordion>

<Accordion title='Plugin SDK additions'>
Plugin developers get three new capabilities: gateway plugins can register applications directly on an Edge Gateway (so access can be granted immediately rather than waiting for the next configuration sync), Studio plugins can read model pricing data, and new text-handling helpers prevent a class of errors when plugins process files in unusual encodings. See the [Plugin SDK Reference](/ai-management/ai-studio/plugins/sdk).
</Accordion>

<Accordion title='OAuth2 client credentials plugin (Enterprise)'>
A new enterprise plugin connects AI Studio to external identity providers such as Auth0, Microsoft Entra ID, and Okta. When a new client authenticates for the first time, the plugin can automatically create its application in AI Studio from a template you define, mapped from the permissions assigned in your identity provider. Providers are managed from a new admin UI screen.
</Accordion>

<Accordion title='Community plugins: rate limiter and model price sync'>
The community plugin collection gains a rate limiter for LLM traffic, with limits on requests, tokens, and concurrent calls that can target specific models or applications. It includes a shadow mode for trying out rules safely before enforcing them. A second new plugin keeps your model pricing table up to date automatically by syncing from a public pricing source on a schedule, with a dry-run mode and dashboard UI.
