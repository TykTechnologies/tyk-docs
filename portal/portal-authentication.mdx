Every API in an API Product must use the same [authentication method](/portal/api-products#authentication-method), because the Portal issues a single credential (for example an Auth Token) to the API Consumer for that Product. This page lists which authentication types the Portal supports, who manages the credentials for each, and how OAuth 2.0 works through Dynamic Client Registration (DCR).

<Note>
This page describes authentication from the Developer Portal's perspective. For how to configure client authentication on Tyk Gateway itself, see [API Authentication](/api-management/client-authentication).
</Note>

## Credential Management: Self-Serve vs Managed

Credentials can be owned by the API Consumer or by the API Owner:

**Self-Serve:** The API Consumer creates, rotates, and revokes their own credentials from the Live Portal.

**Managed:** The API Owner creates and rotates the credentials. The API Consumer can view and revoke them, but can't create or rotate them.

The table below shows which mode applies to each authentication type.

## Supported Authentication Types

| Auth Type | Mode |
|---|---|
| [**Auth Token / API Key**](/api-management/authentication/bearer-token) | Self-Serve |
| [**JWT / OAuth**](/basic-config-and-security/security/authentication-authorization/json-web-tokens) | Self-Serve |
| [**Auth Token + mTLS**](/api-management/implement-tls#using-a-static-client-certificate-allow-list) | Self-Serve or Managed |
| [**JWT + mTLS**](/api-management/implement-tls#using-a-static-client-certificate-allow-list) | Self-Serve or Managed |
| [**Basic Authentication**](/api-management/authentication/basic-authentication) | Managed |
| [**Custom Authentication**](/api-management/authentication/custom-auth) | Managed |

### Unsupported Authentication Types

The Portal doesn't support [HMAC](/basic-config-and-security/security/authentication-authorization/hmac-signatures), [Tyk OAuth 2.0](/api-management/authentication/oauth-2), or [Certificate Auth](/api-management/authentication/certificate-auth). It also doesn't support the deprecated [OpenID Connect (OIDC)](/api-management/client-authentication#integrate-with-openid-connect-deprecated) and [External OAuth](/api-management/client-authentication#integrate-with-external-authorization-server-deprecated) methods, or [Open](/basic-config-and-security/security/authentication-authorization/open-keyless) (keyless) APIs. None of these can be used in an API Product.

## Dynamic Client Registration (DCR) for OAuth 2.0

APIs secured with JSON Web Tokens (JWT) get those tokens from an external Identity Provider (IdP), not from Tyk. So when an API Consumer requests access, the Portal can't just hand them a token the way it does for an Auth Token. Instead, it registers a new OAuth 2.0 client with the IdP on the Consumer's behalf, using [Dynamic Client Registration (DCR)](/tyk-stack/tyk-developer-portal/enterprise-developer-portal/api-access/dynamic-client-registration). The IdP returns a `client_id` and `client_secret`, which the Consumer uses to get a JWT and present to Tyk Gateway. Tyk validates the JWT and creates a [Session](/api-management/access-control/overview#2-dynamically-generated-sessions) on the fly, so there's no need to pre-register the client with Tyk itself.

This is different from the [Authentication Token](/api-management/authentication/bearer-token) method, where Tyk issues the credential directly.

<Note>
The Developer Portal doesn't support the Tyk OAuth 2.0 method, where Tyk itself acts as the auth server.
</Note>

### Supported Identity Providers

| Identity Provider | Support | Notes |
|---|---|---|
| Keycloak | Fully supported | N/A |
| Okta | Fully supported | Requires the `OktaAppType` field (`web`, `native`, `browser`, or `service`). For Client Credentials flow, set the allowed response type to `token` only. |
| Gluu | Fully supported | N/A |
| Curity | Supported via Other type | Curity requires authentication on its DCR endpoint by default. Workaround: disable DCR endpoint authentication in Curity (no-authentication mode). |
| Any RFC-compliant IdP | Supported via Other type | Select **Other** in the DCR template settings. Full compatibility isn't guaranteed. |
