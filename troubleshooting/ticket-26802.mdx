---
title: "Understanding Gateway Latency vs Upstream Latency Breakdown"
description: "Investigation into high p99 gateway latency revealed that Tyk Gateway upstream latency measurement terminates as soon as HTTP response headers are received from the upstream service. Any subsequent duration required for the upstream to stream the response body, or for a slow downstream client to read the response, is calculated as gateway latency (total latency minus upstream latency)."
---

<h2>Overview</h2><p>When analyzing request duration in Tyk Gateway through metrics, access logs, or traffic analytics, latency is split into total latency, upstream latency, and gateway latency. High gateway latency does not always indicate internal middleware or plugin processing bottlenecks.</p><h2>Latency Measurement Breakdown</h2><p>Tyk decomposes latency using the following boundaries:</p><ul><li><strong>Upstream Latency:</strong> Measures the duration from when Tyk Gateway dispatches the request to the upstream target until the upstream service returns HTTP response headers.</li><li><strong>Total Latency:</strong> Measures the entire request lifecycle from when the client request is received by Tyk until the final byte of the response body is transmitted to the client.</li><li><strong>Gateway Latency:</strong> Calculated as total latency minus upstream latency.</li></ul><h2>Response Streaming and Latency Implications</h2><p>Because upstream latency accounting stops once response headers are received, the remaining duration of the response stream is included in gateway latency. Specifically, gateway latency includes:</p><ul><li>Time spent by the upstream service streaming remaining response payload bytes to Tyk.</li><li>Network throughput constraints or transfer delays between Tyk Gateway and the upstream service.</li><li>Slow client consumption where the downstream client takes time reading the response body.</li><li>Internal gateway processing such as middleware, transformations, authentication, and plugins.</li></ul><h2>Diagnostic Considerations</h2><p>If metrics show high gateway latency with low upstream latency, verify the following before assuming internal gateway bottlenecks:</p><ol><li>Inspect response payload sizes and upstream transfer rates.</li><li>Test network latency and bandwidth between Tyk Gateway and upstream hosts.</li><li>Check client-side read speeds and network conditions between clients and the gateway.</li><li>Review gateway debug logs and OpenTelemetry traces to confirm whether internal middleware or plugins are consuming time.</li></ol><h2>Applies To</h2><p>Tyk Gateway version 5.0 and later, Tyk Pump, and Tyk OpenTelemetry tracing integrations.</p>
