---
title: "Amazon Kinesis Pump Record Size Limits and Large Payload Handling"
description: "Tyk Pump documentation for the Amazon Kinesis pump incorrectly cites an outdated 5 MiB batch limit for PutRecords and lacks recommendations for streaming large analytics records."
---

<h2>Overview</h2><p>The Amazon Kinesis pump in Tyk Pump streams API transaction analytics to AWS Kinesis Data Streams using the AWS SDK PutRecords API. Tyk Pump does not enforce internal record or batch payload size constraints; instead, size restrictions are governed by AWS Kinesis service limits.</p><h2>Record and Batch Size Limits</h2><p>AWS Kinesis Data Streams supports payloads up to the following service limits:</p><ul><li><strong>Record size:</strong> AWS allows individual records up to 1 MiB by default, configurable up to 10 MiB in supported AWS regions and stream configurations.</li><li><strong>Batch size:</strong> Each PutRecords request can contain up to 500 records or a total payload size of up to 10 MiB (including partition keys).</li></ul><p><em>Note: Previous documentation referenced a legacy 5 MiB PutRecords limit. Modern Kinesis streams support up to 10 MiB per batch request.</em></p><h2>Recommendations for Large Analytics Payloads</h2><p>When APIs capture request and response payloads, transaction records may become substantially larger. To avoid PutRecords failures due to payload limits, follow these best practices:</p><ol><li><strong>Reduce batch_size:</strong> The batch_size configuration parameter controls the number of records sent per PutRecords API call, not the aggregate byte size. If individual records approach the 10 MiB limit, reduce batch_size (set to 1 if necessary) to avoid exceeding request size limits.</li><li><strong>Limit or omit payloads:</strong> Configure max_record_size to truncate large request and response bodies, or set omit_detailed_recording to true to exclude body data entirely.</li><li><strong>Account for Base64 encoding:</strong> Recorded HTTP request and response bodies undergo Base64 encoding, which expands data size by approximately 33 percent.</li><li><strong>Monitor for delivery failures:</strong> Tyk Pump does not retry rejected records. Enable debug logging with TYK_PMP_LOGLEVEL set to debug to monitor for record-level ingestion errors.</li></ol><h2>Configuration Example</h2><p>Example pump.conf snippet for streaming large payloads to Kinesis:</p><pre><code>{
  &quot;pumps&quot;: {
    &quot;kinesis&quot;: {
      &quot;type&quot;: &quot;kinesis&quot;,
      &quot;meta&quot;: {
        &quot;stream_name&quot;: &quot;tyk-analytics-stream&quot;,
        &quot;region&quot;: &quot;us-east-1&quot;,
        &quot;batch_size&quot;: 1
      },
      &quot;max_record_size&quot;: 1048576,
      &quot;omit_detailed_recording&quot;: false
    }
  }
}</code></pre><h2>Applies To</h2><p>Tyk Pump v1.17.0 and later versions using AWS Kinesis Data Streams.</p>
