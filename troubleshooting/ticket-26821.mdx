---
title: "Multi-Organization Dashboard Users: Credential Requirements and API Key Isolation"
description: "Clarify multi-organization Dashboard user setup regarding identical credential requirements (email and password matching rules) and independent per-organization API access keys."
---

<h2>Overview</h2><p>When enabling multi-organization Dashboard users with <strong>enable_multi_org_users</strong>, users can access multiple organizations using a single login. However, accounts remain distinct user records under each organization.</p><h2>Credential Requirements</h2><p>To enable the Dashboard to link a user across multiple organizations, account records must adhere to the following rules:</p><ul><li><strong>Email Address:</strong> Must be identical across all organizations. The Dashboard identifies and links multi-org user accounts solely by matching email address.</li><li><strong>Password:</strong> Must be identical across all organizations so the user can authenticate into any linked organization with a single password during login and organization switching.</li><li><strong>First and Last Name:</strong> Do not need to match. These are profile display attributes and do not affect account linkage.</li></ul><h2>Dashboard API Keys and Access Control</h2><p>Each organization maintains an independent user record with its own separate API access key and role permissions:</p><ul><li><strong>Distinct API Keys:</strong> Each organization record generates a unique API key. Using an API key from one organization to access Dashboard API endpoints belonging to another organization returns a 401 Unauthorized error. API requests must use the specific access key associated with the target organization.</li><li><strong>Separate Permissions:</strong> Role-based access control and user permissions are configured independently per organization. A user may have administrator privileges in one organization while having read-only permissions in another.</li></ul><h2>Applies To</h2><p>Tyk Dashboard with multi-organization user management enabled (<strong>enable_multi_org_users: true</strong>) and an enterprise multi-team license.</p>
