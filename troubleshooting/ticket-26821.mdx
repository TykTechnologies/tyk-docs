## Overview

When enabling multi-organization Dashboard users with **enable_multi_org_users**, users can access multiple organizations using a single login. However, accounts remain distinct user records under each organization.

## Credential Requirements

To enable the Dashboard to link a user across multiple organizations, account records must adhere to the following rules:

- **Email Address:** Must be identical across all organizations. The Dashboard identifies and links multi-org user accounts solely by matching email address.
- **Password:** Must be identical across all organizations so the user can authenticate into any linked organization with a single password during login and organization switching.
- **First and Last Name:** Do not need to match. These are profile display attributes and do not affect account linkage.

## Dashboard API Keys and Access Control

Each organization maintains an independent user record with its own separate API access key and role permissions:

- **Distinct API Keys:** Each organization record generates a unique API key. Using an API key from one organization to access Dashboard API endpoints belonging to another organization returns a 401 Unauthorized error. API requests must use the specific access key associated with the target organization.
- **Separate Permissions:** Role-based access control and user permissions are configured independently per organization. A user may have administrator privileges in one organization while having read-only permissions in another.

## Applies To

Tyk Dashboard with multi-organization user management enabled (**enable_multi_org_users: true**) and an enterprise multi-team license.
