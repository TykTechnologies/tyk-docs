Tyk packages, Docker images and Helm charts ship with sample values for secrets, so that a new installation starts without extra configuration. These values are the same in every installation. Replace each one with your own value before you deploy to production.

This page lists, for each Tyk component, the secrets to set, the environment variable for each, and the value that Tyk ships. For the steps to follow, start at [Planning for Production](/planning-for-production#change-all-the-shared-secrets).

## How Tyk Reports Default Secrets

Tyk Gateway and Tyk Dashboard log a warning at startup when some settings still have their sample value. They continue to start. The check recognizes only a small number of values, so the absence of a warning does not mean that your secrets are safe. Other components do not check their secrets.

## Generate Values

Use a different random value for each secret, except where this page tells you that two settings must match. To generate a value, use a command such as:

```bash
openssl rand -hex 32
```

In Kubernetes, keep secrets in Kubernetes Secrets and refer to them from your values file. See [Supply Helm Values From Kubernetes Secrets](#supply-helm-values-from-kubernetes-secrets).

## Where the Sample Values Come From

| Installation method | Configuration that Tyk ships |
| :---- | :---- |
| Linux packages (deb and rpm) and the official Docker images | The package installs a sample file as the live configuration file. For example, `tyk.conf.example` becomes `/opt/tyk-gateway/tyk.conf`, `tyk_config_sample.config` becomes `/opt/tyk-dashboard/tyk_analytics.conf`, and `portal.conf` becomes `/opt/portal/portal.conf`. The Docker images install the same packages. |
| Setup scripts in the packages | `/opt/tyk-gateway/install/setup.sh` and `/opt/tyk-dashboard/install/setup.sh` write a configuration file from a template. The scripts do not change the secrets in the template. |
| Helm charts | The `values.yaml` files of the `tyk-stack`, `tyk-control-plane`, `tyk-data-plane` and `tyk-oss` charts set fixed values. |
| Built-in values | Some settings use a value that is built into the component when you do not set them. |

This page does not list the sample values. Treat any secret that you did not generate yourself as a sample value, and replace it.

### Admin User From the Setup Script

The script `/opt/tyk-dashboard/install/bootstrap.sh` creates a Tyk Dashboard user with a fixed password, which is the same in every installation. If you use this script, change the password of that user after you log in for the first time.

The script calls the Tyk Dashboard Admin API with the sample value of `admin_secret`. If you change `admin_secret` before you run the script, edit the script first, or create the first user in the Tyk Dashboard UI.

## Tyk MDCB

Tyk MDCB does not ship sample secrets. Set these values before you go to production.

| Field | Environment variable | Shipped value | Description |
| :---- | :---- | :---- | :---- |
| `security.secret` | `TYK_MDCB_SECURITY_SECRET` | Not set | Authenticates requests to the `/dataplanes`, `/config` and `/env` endpoints. These endpoints are available only when `security.enable_http_secure_endpoints` is `true`. Tyk MDCB does not start if you enable the endpoints and leave the secret empty. |
| [`security.private_certificate_encoding_secret`](/tyk-multi-data-centre/mdcb-configuration-options#security-private_certificate_encoding_secret) | `TYK_MDCB_SECURITY_PRIVATECERTIFICATEENCODINGSECRET` | Not set. Tyk MDCB does not use another value instead. | Decrypts the private keys in the Tyk Certificate Store. Use the same value as Tyk Gateway and Tyk Dashboard in the Control Plane. |
| `storage.password` | `TYK_MDCB_STORAGE_PASSWORD` | Not set | The Redis password. |
| `analytics.connection_string` | `TYK_MDCB_ANALYTICSCONFIG_CONNECTIONSTRING` | No credentials | The MongoDB or PostgreSQL connection string for analytics. |

## Tyk AI Studio

The Linux packages install `/etc/default/tyk-ai-studio` with placeholder values. The AI Studio Helm chart leaves the same values empty.

| Environment variable | Shipped value | Description |
| :---- | :---- | :---- |
| `TYK_AI_SECRET_KEY` | Placeholder value in the Linux packages. Empty in the Helm chart. | Encrypts the secrets that AI Studio stores, such as LLM API keys. When it is empty, AI Studio stores these secrets without encryption and logs a security warning. AI Studio accepts the placeholder value. |
| `GRPC_AUTH_TOKEN` | Placeholder value in the Linux packages. Empty in the Helm chart. | Authenticates Edge Gateways to AI Studio. Set the same value as `EDGE_AUTH_TOKEN` on each Edge Gateway. AI Studio accepts the placeholder value. |
| `MICROGATEWAY_ENCRYPTION_KEY` | Placeholder value in the Linux packages. Empty in the Helm chart. | Encrypts the credentials that AI Studio sends to Edge Gateways. Must be exactly 32 characters, and the same as `ENCRYPTION_KEY` on each Edge Gateway. |

Some example `.env` files in the AI Studio repository contain sample encryption keys of exactly 32 characters. AI Studio and Edge Gateways accept these values. Do not copy them into a deployment.

The AI Studio Helm chart also has these defaults:

| Value | Default | Description |
| :---- | :---- | :---- |
| `database.password` | Sample value | The database password. The chart puts the database URL, with this password, in a ConfigMap. |
| `config.allowRegistrations` | `"true"` | Lets anyone who can reach AI Studio register a user. |
| `config.grpcTlsInsecure` | `"true"` | Disables TLS on the connection between AI Studio and Edge Gateways. |

For the AI Studio settings, see [AI Studio Environment Variables](/ai-management/ai-studio/ai-studio-env).

## Tyk Helm Charts

The Tyk Helm charts do not generate secrets, with one exception: the Tyk Dashboard admin password, when you set it to an empty value. Set these values, or supply them from Kubernetes Secrets.

| Value | Default | Becomes |
| :---- | :---- | :---- |
| `global.secrets.APISecret` | Sample value | `TYK_GW_SECRET`, `TYK_GW_NODESECRET`, `TYK_DB_TYKAPI_SECRET` and `TYK_DB_NODESECRET`. In the `tyk-oss` chart, also the API secret that Tyk Operator uses. |
| `global.secrets.AdminSecret` | Sample value | `TYK_DB_ADMINSECRET` |
| `global.adminUser.email`, `global.adminUser.password` | Sample values | The first Tyk Dashboard user, and the first Developer Portal admin user. The chart generates a random Tyk Dashboard password only when `password` is empty. |
| `tyk-mdcb.mdcb.security.secret` | Sample value | `TYK_MDCB_SECURITY_SECRET` |
| `global.tls.useDefaultTykCertificate` | `true` | When TLS is enabled for Tyk Gateway (`global.tls.gateway: true`), the chart uses a sample certificate and private key that are included in the chart. Set it to `false` and give your own certificate in `tyk-gateway.gateway.tls.secretName`. |
| `global.redis.pass` | Empty | The Redis password |
| `global.postgres.user`, `global.postgres.password`, `global.postgres.sslmode` | `postgres`, no password, `disable` | The PostgreSQL connection of Tyk Dashboard, Tyk MDCB and Tyk Pump |
| `global.mongo.mongoURL` | `mongodb://mongo.<namespace>.svc:27017/tyk_analytics` when it is not set | The MongoDB connection, with no credentials |
| `tyk-dev-portal.storage.s3.awsAccessKeyid`, `tyk-dev-portal.storage.s3.awsSecretAccessKey` | Placeholder values | The S3 credentials of the Developer Portal |

### Supply Helm Values From Kubernetes Secrets

Create the Kubernetes Secret first, then refer to it in your values file. When you refer to a Secret, the chart ignores the plain-text value.

| Values field | Keys in the Kubernetes Secret |
| :---- | :---- |
| `global.secrets.useSecretName` | `APISecret`, `AdminSecret`, `DashLicense`, `OperatorLicense` |
| `global.adminUser.useSecretName` | `adminUserFirstName`, `adminUserLastName`, `adminUserEmail`, `adminUserPassword` |
| `tyk-mdcb.mdcb.useSecretName` | `MDCBLicense`, `securitySecret` |
| `global.remoteControlPlane.useSecretName` (`tyk-data-plane`) | `orgId`, `userApiKey`, `groupID` |
| `global.remoteControlPlane.connectionStringSecretName` (`tyk-data-plane`) | The key in `connectionStringSecretKey`, default `connectionString` |
| `tyk-dev-portal.useSecretName` | `DevPortalLicense`, `DevPortalDatabaseConnectionString`, `DevPortalAwsAccessKeyId`, `DevPortalAwsSecretAccessKey` |
| `tyk-dev-portal.storage.s3.secretRef` | `name`, with the keys in `accessKeyIdKey` and `secretAccessKeyKey` |
| `global.redis.passSecret` | `name`, with the key in `keyName`, default `redisPass` |
| `global.mongo.connectionURLSecret` | `name`, with the key in `keyName`, default `mongoURL` |
| `global.postgres.connectionStringSecret` | `name`, with the key in `keyName`, default `pgConnectionString` |
| `tyk-gateway.gateway.tls.secretName`, `tyk-dashboard.dashboard.tls.secretName`, `tyk-mdcb.mdcb.tls.secretName` | A Kubernetes TLS Secret |

For example, to supply the API secret and the admin secret:

```bash
kubectl create secret generic tyk-secrets -n tyk \
  --from-literal=APISecret="$(openssl rand -hex 32)" \
  --from-literal=AdminSecret="$(openssl rand -hex 32)" \
  --from-literal=DashLicense="$TYK_DASHBOARD_LICENSE"
```

```yaml
global:
  secrets:
    useSecretName: "tyk-secrets"
```

For more detail, see the chart pages: [tyk-stack](/product-stack/tyk-charts/tyk-stack-chart), [tyk-control-plane](/product-stack/tyk-charts/tyk-control-plane-chart), [tyk-data-plane](/product-stack/tyk-charts/tyk-data-plane-chart) and [tyk-oss](/product-stack/tyk-charts/tyk-oss-chart).

## Change the API Secret Safely

When `security.private_certificate_encoding_secret` is empty, Tyk Gateway encrypts the private keys in the Tyk Certificate Store with `secret`, and Tyk Dashboard uses `tyk_api_config.secret`. If you change the API secret, Tyk can no longer read the private keys that it stored before.

To change the API secret on an existing installation:

1. Set `security.private_certificate_encoding_secret` to the current value of `secret` in Tyk Gateway, Tyk Dashboard and Tyk MDCB.
2. Restart the components.
3. Change `secret` in Tyk Gateway and `tyk_api_config.secret` in Tyk Dashboard to the new value.
4. Restart the components.

On a new installation, set `security.private_certificate_encoding_secret` to its own random value before you add certificates.
