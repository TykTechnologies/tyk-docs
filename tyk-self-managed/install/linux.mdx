## Red Hat (RHEL / CentOS)
<a id="install-tyk-on-redhat-rhel-centos"></a>

This section installs four components: the database, Tyk Dashboard, Tyk Pump, and Tyk Gateway.

### Install Database

#### Redis

Tyk Gateway has a [dependency](/planning-for-production/database-settings#redis) on Redis. Follow the Red Hat installation steps for Redis. Use [Red Hat's package search](https://access.redhat.com/search/?q=redis) to find the correct version for your distribution.

#### Storage Database

Tyk Dashboard has a dependency on a storage database that can be [PostgreSQL](/planning-for-production/database-settings#postgresql) or [MongoDB](/planning-for-production/database-settings#mongodb-sizing-guidelines).

<Tabs>

<Tab title="PostgreSQL">

Check the PostgreSQL supported [versions](/planning-for-production/database-settings#postgresql). Follow the steps provided by [PostgreSQL](https://www.postgresql.org/download/linux/redhat/) to install it.

Configure PostgreSQL

Create a new role/user
```console
sudo -u postgres createuser --interactive
```
The name of the role can be "tyk" and say yes to make it a superuser

Create a database with the same name as the role. By default, PostgreSQL requires the login role to have access to a database with the same name.
```console
sudo -u postgres createdb tyk
```
Add a Linux user account to log in to the server.

```console
sudo adduser tyk
```
Log in to your Database
```console
sudo -u tyk psql
```
Update the user “tyk” to have a password
```console
ALTER ROLE tyk with PASSWORD '123456';
```
Create a DB (my example is tyk_analytics)
```console
sudo -u tyk createdb tyk_analytics
```

</Tab>

<Tab title="MongoDB">

Check the MongoDB supported [versions](/planning-for-production/database-settings#mongodb-sizing-guidelines). Follow the steps provided by [MongoDB](https://www.mongodb.com/docs/manual/tutorial/install-mongodb-on-red-hat/) to install it.

Optionally initialize the database and enable automatic start:
```console
# Optionally ensure that MongoDB will start following a system reboot
sudo systemctl enable mongod
# start MongoDB server
sudo systemctl start mongod
```

</Tab>

</Tabs>

### Install Dashboard

Tyk provides signed RPM packages in a YUM repository at [packagecloud.io](https://packagecloud.io/tyk/tyk-dashboard/install#manual-rpm). This lets you install a trusted, verified build of Tyk Dashboard.

This configuration should also work (with some tweaks) for CentOS.

**Prerequisites**

*   Open port `3000` for the Dashboard GUI and the Classic Developer Portal.
*   Follow [Install Tyk on Red Hat (RHEL / CentOS)](#install-tyk-on-redhat-rhel-centos) to install and configure the required Tyk dependencies.

1. **Set up YUM Repositories**

    First, install two package management tools: `yum-utils` and `wget`.
    ```bash
    sudo yum install yum-utils wget
    ```
    Then install Python:
    ```bash
    sudo yum install python3
    ```

2. **Configure and Install the Tyk Dashboard**

    Create a file named `/etc/yum.repos.d/tyk_tyk-dashboard.repo`. Add the repository configuration for `tyk_tyk-dashboard` and `tyk_tyk-dashboard-source` below, with GPG key verification and SSL settings.

    Make sure to replace `el` and `8` in the config below with your Linux distribution and version:
    ```bash
    [tyk_tyk-dashboard]
    name=tyk_tyk-dashboard
    baseurl=https://packagecloud.io/tyk/tyk-dashboard/el/8/$basearch
    repo_gpgcheck=1
    gpgcheck=0
    enabled=1
    gpgkey=https://packagecloud.io/tyk/tyk-dashboard/gpgkey
    sslverify=1
    sslcacert=/etc/pki/tls/certs/ca-bundle.crt
    metadata_expire=300

    [tyk_tyk-dashboard-source]
    name=tyk_tyk-dashboard-source
    baseurl=https://packagecloud.io/tyk/tyk-dashboard/el/8/SRPMS
    repo_gpgcheck=1
    gpgcheck=0
    enabled=1
    gpgkey=https://packagecloud.io/tyk/tyk-dashboard/gpgkey
    sslverify=1
    sslcacert=/etc/pki/tls/certs/ca-bundle.crt
    metadata_expire=300
    ```

    Update the YUM package manager's local cache. Use `--disablerepo='*' --enablerepo='tyk_tyk-dashboard'` to enable only the `tyk_tyk-dashboard` repository, and `-y` to confirm all prompts.
    ```bash
    sudo yum -q makecache -y --disablerepo='*' --enablerepo='tyk_tyk-dashboard'
    ```

    Install Tyk dashboard:
    ```bash
    sudo yum install -y tyk-dashboard
    ```

3. **Confirm Redis and MongoDB or PostgreSQL Have Started**

    Start Redis. The Dashboard always requires it.
    ```bash
    sudo service redis start
    ```
    Then start whichever you use: MongoDB or PostgreSQL.
    ```bash
    sudo systemctl start mongod
    ```
    ```bash
    sudo systemctl start postgresql-13
    ```

4. **Configure Tyk Dashboard**

We can set the Dashboard up with a similar setup command, the script below will get the Dashboard set up for the local instance.
Make sure to use the actual DNS hostname or the public IP of your instance as the last parameter.

<Tabs>
<Tab title="MongoDB">

```bash
sudo /opt/tyk-dashboard/install/setup.sh --listenport=3000 --redishost=<Redis Hostname> --redisport=6379 --mongo=mongodb://<Mongo IP Address>:<Mongo Port>/tyk_analytics --tyk_api_hostname=$HOSTNAME --tyk_node_hostname=http://localhost --tyk_node_port=8080 --portal_root=/portal --domain="XXX.XXX.XXX.XXX"
```

Replace `<Redis Hostname>`, `<Mongo IP Address>` and `<Mongo Port>` with your own values to run this script.

</Tab>
<Tab title="SQL">

```bash
sudo /opt/tyk-dashboard/install/setup.sh --listenport=3000 --redishost=<Redis Hostname> --redisport=6379 --storage=postgres --connection_string=postgresql://<User>:<Password>@<PostgreSQL Hostname>:<PostgreSQL Port>/<PostgreSQL DB> --tyk_api_hostname=$HOSTNAME --tyk_node_hostname=http://localhost --tyk_node_port=8080 --portal_root=/portal --domain="XXX.XXX.XXX.XXX"
```

Replace `<Redis Hostname>`,`<PostgreSQL Hostname>`,`<PostgreSQL Port>`, `<PostgreSQL User>`, `<PostgreSQL Password>` and `<PostgreSQL DB>` with your own values to run the script.

</Tab>
</Tabs>

These values configure the settings below:

*   `--listenport=3000`: Make Tyk Dashboard (and Portal) listen on port `3000`.
*   `--redishost=<hostname>`: Point Tyk Dashboard to the local Redis instance.
*   `--redisport=6379`: Use the default port for Tyk Dashboard.
*   `--domain="XXX.XXX.XXX.XXX"`: Bind Tyk Dashboard to the IP or DNS hostname of this instance (required).
*   `--mongo=mongodb://<Mongo IP Address>:<Mongo Port>/tyk_analytics`: Use the local MongoDB (should always be the same as the Gateway).
*   `--storage=postgres`: If your preferred storage database is PostgreSQL, set the storage type to `postgres` and specify the connection string.
*   `--connection_string=postgresql://<User>:<Password>@<PostgreSQL Host Name>:<PostgreSQL Port>/<PostgreSQL DB>`: Use the PostgreSQL instance in the connection string (should always be the same as the gateway).
*   `--tyk_api_hostname=$HOSTNAME`: Set this to the hostname of Tyk Gateway. This example uses the local `HOSTNAME` environment variable. You can set it to the public hostname or IP address of the instance instead.
*   `--tyk_node_hostname=http://localhost`: Set this to the address of a Tyk Gateway node so Tyk Dashboard can create new tokens. This example points to the Gateway node installed locally.
*   `--tyk_node_port=8080`: Tell the Dashboard that the Tyk node it should communicate with is on port 8080.
*   `--portal_root=/portal`: Serve the Portal at `/portal` on whichever domain you set for it.

5. **Start Tyk Dashboard**

    ```bash
    sudo service tyk-dashboard start
    ```
    

    <Note>
    To check the logs from the deployment run:
    ```bash
    sudo journalctl -u tyk-dashboard 
    ```
    </Note>


    Notice how we haven't actually started the gateway yet, because this is a Dashboard install, we need to enter a license first.

    
<Note>
When using PostgreSQL you may receive the error: `"failed SASL auth (FATAL: password authentication failed for user...)"`, follow these steps to address the issue:
1. Open the terminal or command prompt on your PostgreSQL server.
2. Navigate to the location of the `pg_hba.conf` file. This file is typically located at `/var/lib/pgsql/13/data/pg_hba.conf`.
3. Open the `pg_hba.conf` file using a text manipulation tool.
4. In the `pg_hba.conf` file, find the entry for the user with the authentication error. The entry can look like this:
```bash
host    all    all    <IP_address>/<netmask>    scram-sha-256
```
5. In the entry, find the METHOD column. It currently has the value scram-sha-256.
6. Replace scram-sha-256 with md5, so the modified entry looks like this:
```bash
host    all    all    <IP_address>/<netmask>    md5
```
7. Save the changes you made to the `pg_hba.conf` file.
8. Restart the PostgreSQL service to apply the modifications:
```bash
sudo systemctl restart postgresql-13
```
</Note>


6. **Enter Dashboard license**

    Add your license in `/var/opt/tyk-dashboard/tyk_analytics.conf` in the `license` field.

    If all is going well, you will be taken to a Dashboard setup screen - we'll get to that soon.

7. **Restart the Dashboard process**

    Restart the Dashboard process to pick up the new license. Do this once. If you have Tyk Gateway installed, start it too:
    ```bash
    sudo service tyk-dashboard restart 
    ```

8. **Go to the Tyk Dashboard URL**

    Go to this URL to access the Tyk Dashboard:

    ```bash
    127.0.0.1:3000
    ```

    You should get to the Tyk Dashboard Setup screen:

    <img src="/img/dashboard/system-management/bootstrap_screen.png" alt="Tyk Dashboard Bootstrap Screen" />

9. **Create your Organization and Default User**

    Enter this information:

    * Your **Organization Name**
    * Your **Organization Slug**
    * Your User **Email Address**
    * Your User **First and Last Name**
    * A **Password** for your User
    * **Re-enter** your user **Password**


    

    <Note>
    For a password, we recommend a combination of alphanumeric characters, with both upper and lower case letters.
    </Note>



    Click **Bootstrap** to save the details.

10. **Login to the Dashboard**

    You can now log in to the Tyk Dashboard from `127.0.0.1:3000`, using the username and password created in the Dashboard Setup screen.

    **Configure your Developer Portal**

    To set up your [Developer Portal](/portal/overview/intro) follow our Self-Managed [guide to publish an API to the Portal Catalog](/getting-started/tutorials/publish-api).

### Install Pump


Tyk provides signed RPM packages in a YUM repository at [packagecloud.io](https://packagecloud.io). This lets you install a trusted, verified build of Tyk Pump.

This tutorial will run on an [Amazon AWS](http://aws.amazon.com) *Red Hat Enterprise Linux 7.1* instance. We will install Tyk Pump with all dependencies stored locally.

This tutorial uses a `t2.micro` instance. For better performance, use more RAM and more CPU cores.

This configuration should also work (with some tweaks) for CentOS.

**Prerequisites**

This guide assumes you already installed Redis and either MongoDB or SQL, as part of the Tyk Gateway and Dashboard installation guides.

**Step 1: Set up YUM Repositories**

First, we need to install some software that allows us to use signed packages:
```bash
sudo yum install pygpgme yum-utils wget
```

Next, we need to set up the various repository configurations for Tyk and MongoDB:

Create a file named `/etc/yum.repos.d/tyk_tyk-pump.repo` that contains the repository configuration below: 

Make sure to replace `el` and `7` in the config below with your Linux distribution and version:
```bash
[tyk_tyk-pump]
name=tyk_tyk-pump
baseurl=https://packagecloud.io/tyk/tyk-pump/el/7/$basearch
repo_gpgcheck=1
gpgcheck=1
enabled=1
gpgkey=https://keyserver.tyk.io/tyk.io.rpm.signing.key.2020
       https://packagecloud.io/tyk/tyk-pump/gpgkey
sslverify=1
sslcacert=/etc/pki/tls/certs/ca-bundle.crt
metadata_expire=300
```

Finally we'll need to update our local cache, so run:
```bash
sudo yum -q makecache -y --disablerepo='*' --enablerepo='tyk_tyk-pump'
```

**Step 2: Install Packages**

We're ready to go, you can now install the relevant packages using yum:
```bash
sudo yum install -y tyk-pump
```

**(You may need to accept the GPG key for our repos. Enter yes to continue when the package installs.)**
<br />

**Step 3: Configure Tyk Pump**

Complete this step to enable the analytics service. Tyk Pump must run, with the correct configuration, or the Dashboard shows no analytics.


**Configure Tyk Pump for MongoDB**
<br />

<Note>
You need to replace `<hostname>` for `--redishost=<hostname>`, and `<Mongo IP Address>`, `<Mongo Port>`  for `--mongo=mongodb://<Mongo IP Address>:<Mongo Port>/` with your own values to run this script.
</Note>


```bash
sudo /opt/tyk-pump/install/setup.sh --redishost=<hostname> --redisport=6379 --mongo=mongodb://<IP Address>:<Mongo Port>/tyk_analytics
```

**Configure Tyk Pump for SQL**
<br />

<Note>

### Install Dashboard
<a id="Debian-Ubuntu-install-dashboard"></a>


Tyk provides its own APT repositories at [packagecloud.io](https://packagecloud.io/tyk). This lets you install a trusted, verified build of Tyk Dashboard.

We tested this tutorial on Ubuntu 16.04 and 18.04, with few if any modifications. We will install the Tyk Dashboard with all dependencies locally.

**Prerequisites**
- Have MongoDB/SQL and Redis installed. Follow the guide to [install databases on Debian or Ubuntu](#install-tyk-on-debian-or-ubuntu).
- Open port `3000`. The Tyk Dashboard uses it for the GUI and the Developer Portal.

**Step 1: Set up our APT Repositories**

First, add our GPG key which signs our binaries:

```bash
curl -L https://packagecloud.io/tyk/tyk-dashboard/gpgkey | sudo apt-key add -
```

Run update:

```bash
sudo apt-get update
```

Our repositories use HTTPS. Make sure APT supports this:

```bash
sudo apt-get install -y apt-transport-https
```

Now lets add the required repos and update again (notice the `-a` flag in the second Tyk commands - this is important!):

```bash
echo "deb https://packagecloud.io/tyk/tyk-dashboard/ubuntu/ bionic main" | sudo tee /etc/apt/sources.list.d/tyk_tyk-dashboard.list

echo "deb-src https://packagecloud.io/tyk/tyk-dashboard/ubuntu/ bionic main" | sudo tee -a /etc/apt/sources.list.d/tyk_tyk-dashboard.list

sudo apt-get update
```


<Note>
`bionic` is the code name for Ubuntu 18.04. Please substitute it with your particular [ubuntu release](https://releases.ubuntu.com/), e.g. `focal`.
</Note>


This adds the Tyk Dashboard repository and updates the package list.

**Step 2: Install the Tyk Dashboard**

Install the Tyk Dashboard:

```bash
sudo apt-get install -y tyk-dashboard
```

This tells `apt-get` to install the Tyk Dashboard without prompts. Wait for the downloads to complete.

After the Tyk Dashboard installation finishes, it has some `init` scripts, but it isn't active yet. Three simple commands set up each application in the next step.

**Verify the origin key (optional)**

The repository keys sign Debian packages. The `apt` infrastructure verifies these keys automatically when it fetches a package. PackageCloud, our repository provider, controls these keys. For extra assurance, check the `origin` certificate attached to the package. It confirms that Tyk created the package.

First, you have to fetch Tyk's signing key and import it.

```bash
wget https://keyserver.tyk.io/tyk.io.deb.signing.key
gpg --import tyk.io.deb.signing.key
```

Then, you have to either,
- sign the key with your ultimately trusted key
- trust this key ultimately

Find the downloaded package in `/var/cache/apt/archives` (for example, `tyk-gateway-2.9.4_amd64.deb`). Then verify the origin signature.

```bash
gpg --verify d.deb
gpg: Signature made Wed 04 Mar 2020 03:05:00 IST
gpg:                using RSA key F3781522A858A2C43D3BC997CA041CD1466FA2F8
gpg: Good signature from "Team Tyk (package signing) <team@tyk.io>" [ultimate]
```

### Install Pump

We tested this tutorial on Ubuntu 16.04 and 18.04, with few if any modifications.

**Prerequisites**

- Have Redis and either MongoDB or SQL installed.
- Have the Tyk Dashboard installed.

**Step 1: Set up our APT repositories**

First, add our GPG key which signs our binaries:

```bash
curl -L https://packagecloud.io/tyk/tyk-pump/gpgkey | sudo apt-key add -
```

Run update:

```bash
sudo apt-get update
```

Our repositories use HTTPS. Make sure APT supports this:

```bash
sudo apt-get install -y apt-transport-https
```

Now lets add the required repos and update again (notice the `-a` flag in the second Tyk commands - this is important!):

```bash
echo "deb https://packagecloud.io/tyk/tyk-pump/ubuntu/ bionic main" | sudo tee /etc/apt/sources.list.d/tyk_tyk-pump.list

echo "deb-src https://packagecloud.io/tyk/tyk-pump/ubuntu/ bionic main" | sudo tee -a /etc/apt/sources.list.d/tyk_tyk-pump.list

sudo apt-get update
```


<Note>
`bionic` is the code name for Ubuntu 18.04. Please substitute it with your particular [ubuntu release](https://releases.ubuntu.com/), e.g. `focal`.
</Note>


This adds the Tyk Pump repository and updates the package list.

**Step 2: Install the Tyk Pump**

Install the Tyk Pump:

```bash
sudo apt-get install -y tyk-pump
```

This tells `apt-get` to install Tyk Pump without prompts. Wait for the downloads to complete.

After the Tyk Pump installation finishes, it has some `init` scripts, but it isn't active yet. Three simple commands set up each application in the next step.

**Verify the origin key (optional)**

The repository keys sign Debian packages. The `apt` infrastructure verifies these keys automatically when it fetches a package. PackageCloud, our repository provider, controls these keys. For extra assurance, check the `origin` certificate attached to the package. It confirms that Tyk created the package.

First, you have to fetch Tyk's signing key and import it.

```bash
wget https://keyserver.tyk.io/tyk.io.deb.signing.key
gpg --import tyk.io.deb.signing.key
```

Then, you have to either,
- sign the key with your ultimately trusted key
- trust this key ultimately

Find the downloaded package in `/var/cache/apt/archives` (for example, `tyk-gateway-2.9.3_amd64.deb`). Then verify the origin signature.

```bash
gpg --verify d.deb
gpg: Signature made Wed 04 Mar 2020 03:05:00 IST
gpg:                using RSA key F3781522A858A2C43D3BC997CA041CD1466FA2F8
gpg: Good signature from "Team Tyk (package signing) <team@tyk.io>" [ultimate]
```

### Install Gateway
<a id="debian-ubuntu-install-gateway"></a>


Tyk provides its own APT repositories at [packagecloud.io][1]. This lets you install a trusted, verified build of Tyk Gateway.

We tested this tutorial on Ubuntu 16.04 and 18.04, with few if any modifications.

Note that Tyk currently has a Python version dependency of 3.4 for custom plugins written in Python. Python 3.4 ships with Ubuntu 14.04. On newer Ubuntu releases, you may need to install it explicitly.

**Prerequisites**

*   Open port `8080`. This guide uses it for Gateway traffic, to proxy API traffic.
*   Have MongoDB and Redis installed.
*   Have the Tyk Dashboard installed, then the Tyk Pump.

**Step 1: Set up our APT Repositories**

First, add our GPG key which signs our binaries:

```bash
curl -L https://packagecloud.io/tyk/tyk-gateway/gpgkey | sudo apt-key add -
```

Run update:
```bash
sudo apt-get update
```

Our repositories use HTTPS. Make sure APT supports this:
```bash
sudo apt-get install -y apt-transport-https 
```

Create a file `/etc/apt/sources.list.d/tyk_tyk-gateway.list` with this content:
```bash
deb https://packagecloud.io/tyk/tyk-gateway/ubuntu/ bionic main
deb-src https://packagecloud.io/tyk/tyk-gateway/ubuntu/ bionic main
```

<Note>
`bionic` is the code name for Ubuntu 18.04. Please substitute it with your particular [ubuntu release](https://releases.ubuntu.com/), e.g. `focal`.
</Note>


Now you can refresh the list of packages with:
```bash
sudo apt-get update
```

This adds the Tyk Gateway repository and updates the package list.

**Step 2: Install the Tyk Gateway**

Install the Tyk Gateway:

```bash
sudo apt-get install -y tyk-gateway
```
This tells `apt-get` to install the Tyk Gateway without prompts. Wait for the downloads to complete.

After the Tyk installation finishes, it has some init scripts, but it isn't active yet. Three simple commands set up the Gateway in the next step. The exact commands depend on whether you use Tyk Gateway with the Dashboard or on its own (the Community Edition).

**Verify the origin key (optional)**

The repository keys sign Debian packages. The `apt` infrastructure verifies these keys automatically when it fetches a package. PackageCloud, our repository provider, controls these keys. For extra assurance, check the `origin` certificate attached to the package. It confirms that Tyk created the package.

First, you have to fetch Tyk's signing key and import it.

```bash
wget https://keyserver.tyk.io/tyk.io.deb.signing.key
gpg --import tyk.io.deb.signing.key
```

Then, you have to either,
- sign the key with your ultimately trusted key
- trust this key ultimately

Find the downloaded package in `/var/cache/apt/archives` (for example, `tyk-gateway-2.9.4_amd64.deb`). Then verify the origin signature.

```bash
gpg --verify d.deb
gpg: Signature made Wed 04 Mar 2020 03:05:00 IST
gpg:                using RSA key F3781522A858A2C43D3BC997CA041CD1466FA2F8
gpg: Good signature from "Team Tyk (package signing) <team@tyk.io>" [ultimate]
```

**Configure Tyk Gateway with Dashboard**

**Prerequisites**

This configuration assumes that you already installed the Tyk Dashboard, and decided on the domain names for your Dashboard and your Portal. **They must be different**. To test this, add hosts entries to your `/etc/hosts` file (and your server's).

**Set up Tyk**

You can set up the core settings for Tyk Gateway with a single setup script. For more involved deployments, provide your own configuration file.


<Note>
You need to replace `<hostname>` for `--redishost=<hostname>`with your own value to run this script.
</Note>



```bash
sudo /opt/tyk-gateway/install/setup.sh --dashboard=1 --listenport=8080 --redishost=<hostname> --redisport=6379
```

This configures the setup script:

*   `--dashboard=1`: Use the Dashboard. Tyk Gateway gets all its API definitions from the Dashboard service. Since v2.3, Tyk auto-detects the location of the Dashboard, so this flag only needs to specify that mode.
*   `--listenport=8080`: Listen on port `8080` for API traffic.
*   `--redishost=<hostname>`: Use Redis on your hostname.
*   `--redisport=6379`: Use the default Redis port.

**Start Tyk**

Start the Tyk Gateway now that it has the right configuration. Use this command:
```bash
sudo service tyk-gateway start
sudo service tyk-gateway enable
```

**Pro Tip: Domains with Tyk Gateway**

Tyk Gateway has full domain support built-in, you can:

*   Set Tyk to listen only on a specific domain for all API traffic.
*   Set an API to listen on a specific domain (e.g. api1.com, api2.com).
*   Split APIs over a domain using a path (e.g. api.com/api1, api.com/api2, moreapis.com/api1, moreapis.com/api2 etc).
*   If you have set a hostname for the Gateway, then all non-domain-bound APIs will be on this hostname + the `listen_path`.
