## Introduction

If you want to set up multi-tenant API management with Tyk, follow these steps to define an OperatorContext for connecting and authenticating with a Tyk Dashboard and reference it in your API definitions for specific configurations.

## Defining OperatorContext

An [OperatorContext](/api-management/automations/operator#multi-tenancy-in-tyk) specifies the parameters for connecting and authenticating with a Tyk Dashboard. Below is an example of how to define an `OperatorContext`:

```yaml
apiVersion: tyk.tyk.io/v1alpha1
kind: OperatorContext
metadata:
  name: team-alpha
  namespace: default
spec:
  env:
    # The mode of the admin api
    # ce - community edition (open source gateway)
    # pro - dashboard (requires a license)
    mode: pro
    # Org ID to use
    org: *YOUR_ORGANIZATION_ID*
    # The authorization token this will be set in x-tyk-authorization header on the
    # client while talking to the admin api
    auth: *YOUR_API_ACCESS_KEY*
    # The url to the Tyk Dashboard API
    url: http://dashboard.tyk.svc.cluster.local:3000
    # Set this to true if you want to skip tls certificate and host name verification
    # this should only be used in testing
    insecureSkipVerify: true
    # For ingress the operator creates and manages ApiDefinition resources, use this to configure
    # which ports the ApiDefinition resources managed by the ingress controller binds to.
    # Use this to override default ingress http and https port
    ingress:
      httpPort: 8000
      httpsPort: 8443
```

For better security, you can also replace sensitive data with values contained within a referenced secret with `.spec.secretRef`.

In this example, API access key `auth` and organization ID `org` are not specified in the manifest. They are provided through a Kubernetes secret named `tyk-operator-conf` in `alpha` namespace. The secret contains keys `TYK_AUTH` and `TYK_ORG` which correspond to the `auth` and `org` fields respectively.

```yaml
apiVersion: tyk.tyk.io/v1alpha1
kind: OperatorContext
metadata:
  name: team-alpha
  namespace: default
spec:
  secretRef:
    name: tyk-operator-conf# Secret containing keys TYK_AUTH and TYK_ORG
    namespace: alpha
  env:
    mode: pro
    url: http://tyk.tykce-control-plane.svc.cluster.local:8001
    insecureSkipVerify: true
    ingress:
      httpPort: 8000
      httpsPort: 8443
    user_owners:
    - a1b2c3d4f5e6f7
    user_group_owners:
    - 1a2b3c4d5f6e7f
```

You can provide the following fields through secret as referenced by `secretRef`. The table shows mappings between `.spec.env` properties and secret `data` keys. If you set a value in both the secret and the OperatorContext `spec.env` field, the value from `spec.env` takes precedence. Tyk Operator reads a key from the secret only when the matching `spec.env` field is empty.

| Secret key | .spec.env |
| :------------ | :----------- |
| TYK_MODE	 | mode |
| TYK_URL    | url |
| TYK_AUTH	 | auth |
| TYK_ORG	   | org |
| TYK_TLS_INSECURE_SKIP_VERIFY | insecureSkipVerify |
| TYK_USER_OWNERS (comma separated list) | user_owners |
| TYK_USER_GROUP_OWNERS (comma separated list) | user_group_owners |
| TYK_PORTAL_URL | portal_url |
| TYK_PORTAL_AUTH | portal_auth |

## Connect an OperatorContext to the Developer Portal

<Note>Available from Tyk Operator 1.7.0</Note>

The Tyk Developer Portal has its own address and its own admin API token. The Tyk Dashboard token does not work on it. To let Tyk Operator connect to the Developer Portal, set these optional fields in `spec.env`:

| Field | Description |
| :---- | :---------- |
| `portal_url` | The address of the Developer Portal admin API. The address must include the `/portal-api` path, for example `http://portal.tyk.svc.cluster.local:3001/portal-api`. If a proxy adds a path prefix, include the prefix too, for example `https://example.com/devportal/portal-api`. |
| `portal_auth` | The admin API token of a Developer Portal admin user. Tyk Operator can do only what this user can do. Use a user with the *provider-admin* role. |

If you do not use the Developer Portal, leave both fields empty. An `OperatorContext` without these fields has no Developer Portal connection.

Keep the token in the secret that `secretRef` references, under the `TYK_PORTAL_AUTH` key. Do not write it in the manifest. Tyk Operator does not write the token to the `OperatorContext` status or to its logs.

```yaml
apiVersion: tyk.tyk.io/v1alpha1
kind: OperatorContext
metadata:
  name: team-alpha
  namespace: default
spec:
  secretRef:
    name: tyk-operator-conf # Secret containing keys TYK_AUTH, TYK_ORG and TYK_PORTAL_AUTH
    namespace: alpha
  env:
    mode: pro
    url: http://dashboard.tyk.svc.cluster.local:3000
    portal_url: http://portal.tyk.svc.cluster.local:3001/portal-api
```

### Get the Developer Portal Token

1. Log in to the Admin Portal of the Developer Portal as the user that Tyk Operator will act as.
2. Open your profile page.
3. Copy the token from **Personal credentials to access portal APIs**.

The token does not expire. It becomes invalid in these cases:

- A user selects **Reset Credential** on the profile page of that user.
- The Developer Portal JWT signing key changes.

In both cases, get the new token and update the secret.

### Check the Connection

Tyk Operator checks the connection when the `OperatorContext` or its secret changes. While a Developer Portal is configured, Tyk Operator also checks the connection again every 5 minutes. Tyk Operator writes the result to `status.tyk_portal`:

```bash
kubectl get operatorcontext team-alpha -o jsonpath='{.status.tyk_portal}'
```

The `state` field has one of these values. The `reason` field explains any state other than `Connected`.

| State | Meaning | Action |
| :---- | :------ | :----- |
| `Connected` | The Developer Portal accepted the token. | None. |
| `Refused` | The Developer Portal rejected the token. | Replace the token, or make sure the user has the *provider-admin* role. |
| `Unavailable` | Tyk Operator cannot reach the Developer Portal, the Developer Portal returned an error other than `403`, or the response did not come from the admin API. | Make sure that `portal_url` includes `/portal-api`. Make sure that the Developer Portal is running and its license is valid. |
| `Misconfigured` | The `OperatorContext` has an address without a token, or a token without an address. Tyk Operator does not contact the Developer Portal. | Add the missing value. |

If you do not configure a Developer Portal, the `status.tyk_portal` field is not present. If a Developer Portal check fails, Tyk Operator continues to manage the Tyk Dashboard resources that use the `OperatorContext`.

## Using contextRef in API Definitions

Once an `OperatorContext` is defined, you can reference it in your API Definition objects using `contextRef`. Below is an example:

```yaml
apiVersion: tyk.tyk.io/v1alpha1
kind: ApiDefinition
metadata:
  name: httpbin
  namespace: alpha
spec:
  contextRef:
    name: team-alpha
    namespace: default
  name: httpbin
  use_keyless: true
  protocol: http
  active: true
  proxy:
    target_url: http://httpbin.org
    listen_path: /httpbin
    strip_listen_path: true
```

In this example, the `ApiDefinition` object references the `team-alpha` context, ensuring that the configuration is applied within the `alpha` organization.
