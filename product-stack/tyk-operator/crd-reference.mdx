## TykIdentityProfile CRD Reference

The `TykIdentityProfile` Custom Resource Definition (CRD) allows platform teams to declaratively manage Tyk Identity Broker (TIB) profiles within Kubernetes.

### Specification Fields (`spec`)

| Field | Type | Description |
|---|---|---|
| `name` | string | The descriptive name of the identity profile. |
| `action_type` | string | Profile action type: `GenerateOrLoginUserProfile` (Dashboard users) or `GenerateOrLoginDeveloperProfile` (Developer Portal consumers). |
| `idp` | string | Identity provider type (e.g. `oidc`, `saml`, `social`, `ldap`). |
| `provider_config` | object | Provider-specific authentication parameters (Client ID, Client Secret, Discovery URL). |
| `identity_handler_config` | object | Target Dashboard or Portal parameters including `dashboard_credential` and redirect paths. |

### Configuration Example (OIDC Profile)

```yaml
apiVersion: tyk.tyk.io/v1alpha1
kind: TykIdentityProfile
metadata:
  name: oidc-developer-profile
  namespace: tyk
spec:
  name: "OIDC Developer Profile"
  action_type: "GenerateOrLoginDeveloperProfile"
  idp: "oidc"
  provider_config:
    issuer: "https://idp.example.com"
    client_id: "tyk-portal-client"
    client_secret: "secret-key"
    callback_url: "https://portal.example.com/auth/callback"
  identity_handler_config:
    dashboard_credential: "portal-api-secret"
    redirect_uri: "https://portal.example.com"
```
