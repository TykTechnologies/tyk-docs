The Tyk Gateway API is the primary means for integrating your application with the Tyk API Gateway system. This API is very small, and has no granular permissions system. It is intended to be used purely for internal automation and integration.

**Warning: Under no circumstances should outside parties be granted access to this API.**

With the Tyk Gateway API, you can:

* Manage session objects (key generation).
* Manage and list Policies.
* Manage and list API definitions.
* Reload a Tyk Gateway or a cluster of Tyk Gateways.
* Manage OAuth clients.

In order to use the Gateway API, you'll need to set the **secret** parameter in your tyk.conf file.

The shared secret you set should then be sent along as a header with each Gateway API Request in order for it to be successful:

`x-tyk-authorization: <your-secret>`
<br/>

## Tyk Gateway API and Tyk Dashboard API

If you use Tyk Dashboard, use the [Tyk Dashboard API](/tyk-dashboard-api) for most tasks. Tyk Dashboard stores APIs and Policies in its database. When you change them, Tyk Dashboard tells Tyk Gateway to reload, and Tyk Gateway loads the changes from Tyk Dashboard. For keys, OAuth clients and certificates, the Tyk Dashboard API calls the Tyk Gateway API for you.

The Tyk Dashboard API does not cover every Tyk Gateway API operation. The table below compares the two APIs.

| Task | Tyk Gateway API | Tyk Dashboard API |
| :--- | :--- | :--- |
| Manage API definitions | `/tyk/apis/oas`, `/tyk/apis` | `/api/apis/oas`, `/api/apis` |
| Import, export and list versions of a Tyk OAS API | `POST /tyk/apis/oas/import`, `GET /tyk/apis/oas/{apiID}/export`, `GET /tyk/apis/oas/{apiID}/versions` | `POST /api/apis/oas/import`, `GET /api/apis/oas/{apiId}/export`, `GET /api/apis/oas/{apiId}/versions` |
| Get the API definition schema | `GET /tyk/schema` | `GET /api/schema` |
| Manage MCP proxies | `/tyk/mcps` | `/api/mcps` |
| Manage Policies | `/tyk/policies` | `/api/portal/policies` |
| Manage keys | `/tyk/keys` | `/api/keys` |
| Preview a key | `POST /tyk/keys/preview` | `POST /api/keys/preview` |
| Set the Policies of a hashed key | `POST /tyk/keys/policy/{keyID}` | Not available. Update the key with `PUT /api/keys/{keyId}`. |
| Manage OAuth clients | `/tyk/oauth/clients` | `/api/apis/oauth` |
| List the tokens of an OAuth client | `GET /tyk/oauth/clients/{apiID}/{keyName}/tokens` | `GET /api/apis/oauth/{apiId}/{clientId}/tokens` |
| List the APIs of an OAuth client | `GET /tyk/oauth/clients/apis/{appID}` | Not available |
| Revoke OAuth tokens | `POST /tyk/oauth/revoke`, `POST /tyk/oauth/revoke_all` | `POST /api/apis/oauth/{appId}/revoke`, `POST /api/apis/oauth/{appId}/revoke_all` |
| Rotate an OAuth client secret | `PUT /tyk/oauth/clients/{apiID}/{keyName}/rotate` | Not available |
| Invalidate an OAuth refresh token | `DELETE /tyk/oauth/refresh/{keyName}` | Not available |
| Purge lapsed OAuth tokens | `DELETE /tyk/oauth/tokens` | `DELETE /admin/oauth/tokens` in the [Tyk Dashboard Admin API](/dashboard-admin-api) |
| Manage certificates | `/tyk/certs` | `/api/certs` |
| Manage Organisation quotas | `/tyk/org/keys` | `/admin/org/keys` in the [Tyk Dashboard Admin API](/dashboard-admin-api) |
| Invalidate the cache of an API | `DELETE /tyk/cache/{apiID}` | `DELETE /api/cache/{apiId}` |
| Invalidate the JWKS cache | `DELETE /tyk/cache/jwks/{apiID}` for one API, `DELETE /tyk/cache/jwks` for all APIs | `DELETE /api/cache/jwks/{apiId}` for one API. Not available for all APIs. |
| Debug an API | `POST /tyk/debug` | `POST /api/debug` |
| Reload Tyk Gateway | `GET /tyk/reload`, `GET /tyk/reload/group` | Not available. Tyk Dashboard tells Tyk Gateway to reload when you change an API or a Policy. |
| Check the health of Tyk Gateway | `GET /hello`, `GET /ready` | Not available |

If [`use_db_app_configs`](/tyk-oss-gateway/configuration#use_db_app_configs) is `true`, Tyk Gateway loads its APIs from Tyk Dashboard. In this mode, Tyk Gateway rejects requests to create, update, delete, import or patch an API through the Tyk Gateway API. It returns this error:

```text
Due to enabled use_db_app_configs, please use the Dashboard API
```

If [`policies.policy_source`](/tyk-oss-gateway/configuration#policies-policy_source) is `service`, Tyk Gateway also rejects requests to create or update a Policy through the Tyk Gateway API. It returns this error:

```text
Due to enabled service policy source, please use the Dashboard API
```

Tyk Gateway does not reject all the other write requests in these modes, but they do not work:

- A request to delete a Tyk Classic API, an MCP proxy or a Policy fails with the `Delete failed` error. Tyk Gateway has no local file to delete.
- A request to create or update an MCP proxy succeeds. Tyk Gateway writes the MCP proxy only to a local file. Tyk Gateway loads MCP proxies only from Tyk Dashboard, so it does not load this MCP proxy.

Use the Tyk Dashboard API for these operations.

In a Tyk MDCB data plane, Tyk Gateway gets its configuration from the control plane. If the data plane Tyk Gateway uses the `rpc` storage engine in `auth_override`, it does not serve these Tyk Gateway API endpoints:

- `/tyk/apis`, `/tyk/policies`, `/tyk/mcps` and `/tyk/org/keys`
- `POST /tyk/keys/create` and `POST /tyk/keys/policy/{keyName}`
- `GET /tyk/health`
- The OAuth endpoints that create, update or rotate a client
- The OAuth endpoint that lists the APIs of a client
- The OAuth endpoints that revoke tokens or invalidate a refresh token
