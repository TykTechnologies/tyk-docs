## Availability

| Edition | Deployment Type |
| :------------- | :---------------------- |
| [Community](/ai-management/ai-studio/overview#community-edition) & [Enterprise](/ai-management/ai-studio/overview#enterprise-edition) | Self-Managed |

FIPS 140-3 builds are available from Tyk AI Studio 2.3.0. Packages are available for both editions. Container images are available for the Enterprise Edition only.

## Overview

AI Studio and the Edge Gateway (the microgateway) are available as FIPS 140-3 compliant builds. For what "FIPS-compliant" means and the Tyk FIPS policy, refer to [FIPS 140-3 Compliance](/developer-support/release-types/fips-release). A small number of non-approved read paths remain. Refer to [Known Exceptions](#known-exceptions).

The standard builds do not change. A database can move from a standard build to a FIPS build, and back. Refer to [Data Formats](#data-formats).

## The Validated Module

The FIPS builds use the **Go Cryptographic Module v1.0.0**. This module has [CMVP certificate #5247](https://csrc.nist.gov/projects/cryptographic-module-validation-program/certificate/5247). The build selects the module with `GOFIPS140=v1.0.0`.

A FIPS build starts in FIPS mode. In FIPS mode, TLS, hashing, HMAC, key derivation and encryption use the approved algorithms of the module.

## Packages and Images

| Component | DEB and RPM Package | Container Image |
| :-------- | :------------------ | :-------------- |
| AI Studio | `tyk-ai-studio-fips` (Community Edition), `tyk-ai-studio-fips-ee` (Enterprise Edition) | `tykio/tyk-ai-studio-fips` |
| Edge Gateway (server and `mgw` CLI) | `tyk-microgateway-fips` (Community Edition), `tyk-microgateway-fips-ee` (Enterprise Edition) | `tykio/tyk-microgateway-fips` |

- Packages are available for amd64, arm64 and s390x. Images are available for amd64 and arm64.
- The FIPS packages and images use the same repositories, paths, ports and settings as the standard ones. To install them, follow [Install Tyk AI Studio on Linux](/ai-management/ai-studio/installation/linux) or [Install Tyk AI Studio on Kubernetes](/ai-management/ai-studio/deployment-k8s). Change the package names, or the image repositories. In the Helm chart, these are `midsommar.image.repository` and `microgateway.image.repository`.
- A FIPS package installs to the same paths as the standard package. Install only one of the two packages on a host.
- Tyk builds the images from the Enterprise Edition packages, on the Tyk FIPS base image. Each image has a provenance attestation and an SBOM attestation. The images run as user ID 65532.

<Warning>
Packages with `-fips` names that Tyk published before release 2.3.0 are standard builds. Do not use them for a FIPS deployment.
</Warning>

## Check That FIPS Mode Is On

An environment variable can turn FIPS mode off in a FIPS build. Refer to [FIPS Modes](#fips-modes). The package or image name therefore does not prove that FIPS mode is on. Check the status that the process reports:

| Value | Description |
| :---- | :---------- |
| `enabled` | `true` when FIPS mode is on. |
| `version` | The version of the Go Cryptographic Module, for example `v1.0.0-c2097c7c`. |
| `enforced` | `true` when the process refuses all non-approved algorithms (`GODEBUG=fips140=only`). |

- **Startup log**: AI Studio and the Edge Gateway log a `FIPS 140-3` entry with the three values when they start.
- **Health endpoint**: `GET /health` on AI Studio and on the Edge Gateway returns a `fips` object with the three values:

  ```json
  {"status": "ok", "fips": {"enabled": true, "version": "v1.0.0-c2097c7c", "enforced": false}}
  ```

- **Edge Gateways page**: AI Studio shows the status that each edge reports in its heartbeat. Refer to [Manage Edge Gateway for Tyk AI Studio](/ai-management/ai-studio/manage-edge-gateway).

## FIPS Modes

The `GODEBUG` environment variable sets the FIPS mode of a FIPS build at run time.

| Variable | Default | Description |
| :------- | :------ | :---------- |
| `GODEBUG=fips140=on` | On in FIPS builds | FIPS mode. The process uses the approved algorithms of the module. |
| `GODEBUG=fips140=off` | - | Turns FIPS mode off, also in a FIPS build. The status shows `"enabled": false`. |
| `GODEBUG=fips140=only` | - | Strict mode. The process also refuses all non-approved algorithms. The status shows `"enforced": true`. Use this mode for tests. |

## Data Formats

A process in FIPS mode writes data in approved formats. Every build of AI Studio 2.3 reads the old formats and the new formats.

| Data | Standard Build Writes | FIPS Build Writes |
| :--- | :-------------------- | :---------------- |
| Secrets at rest (encrypted with `TYK_AI_SECRET_KEY`) | `v2:` format (scrypt and AES-GCM) | `v3:` format (PBKDF2-HMAC-SHA256 and AES-GCM) |
| User passwords, OAuth client secrets, Edge Gateway credential secrets | bcrypt | PBKDF2-HMAC-SHA256 |

- **Secrets**: When AI Studio starts in FIPS mode, it re-encrypts stored secrets to the `v3:` format in the background. This includes the values on the **Secrets** page. It also includes encrypted values in other records, such as LLM API keys and webhook headers. Until the work is complete, AI Studio continues to read the older values. When it is complete, AI Studio logs the number of re-encrypted values. A standard build does not re-encrypt secrets. Refer to [Secrets Management](/ai-management/ai-studio/secrets).
- **Passwords and client secrets**: AI Studio replaces a bcrypt password hash at the next login of the user. It replaces the hash of an OAuth client secret at the next successful authentication of the client.

## Move an Existing Deployment to FIPS Builds

1. Take a database backup.
2. Make sure that your TLS endpoints, certificates and keys meet the [requirements](#tls-and-key-requirements).
3. If you use PostgreSQL, set it to use SCRAM-SHA-256 password authentication. Do not use `md5`.
4. Replace each plugin with a FIPS build of the plugin (OCI tag `<version>-fips`). Each plugin does its own cryptography. A deployment is compliant only when each plugin is a FIPS build. In FIPS mode, the host logs a warning for a plugin that is not a FIPS build. Refer to [FIPS Plugin Variants](/ai-management/ai-studio/plugins/security#fips-plugin-variants).
5. Rotate the signing key of each LLM that shows `Derived from the API key (not upgraded yet)` in **Native API resource IDs**. FIPS mode derives a different key. Resource IDs from a standard build then do not verify. Refer to [Native API Resource IDs](/ai-management/ai-studio/llm-management#native-api-resource-ids).
6. Replace the AI Studio and Edge Gateway packages or images with the FIPS packages or images.
7. Start AI Studio in FIPS mode (the default). Wait for the log line that gives the number of re-encrypted secrets.
8. [Check that FIPS mode is on](#check-that-fips-mode-is-on) for AI Studio and for each Edge Gateway.
9. Optional: To test that no non-approved algorithm is in use, set `GODEBUG=fips140=only`.

<Note>
In strict mode (`GODEBUG=fips140=only`), AI Studio can read secrets that are older than the `v2:` format (AES-CFB) only during the startup re-encryption. Start AI Studio one time in FIPS mode, and let the re-encryption complete, before you use strict mode.
</Note>

### TLS and Key Requirements

FIPS mode accepts only TLS 1.2 and TLS 1.3, with approved cipher suites and curves. This applies to connections to LLM vendors, between AI Studio and the Edge Gateways, to gRPC plugins, and to your own TLS endpoints.

- A peer that offers only ChaCha20-Poly1305, or only X25519 key exchange, cannot connect.
- FIPS mode accepts the hybrid post-quantum key exchange X25519MLKEM768 of TLS 1.3.
- Options that skip TLS certificate verification are outside the scope of FIPS compliance. Do not use them.

| Key | Permitted Types | Notes |
| :-- | :-------------- | :---- |
| TLS certificates | RSA (2048 bits or more), ECDSA (P-256, P-384, P-521), Ed25519 | FIPS mode and strict mode refuse other keys. |
| Plugin signing keys, JWKS of SSO identity providers | RSA (2048 bits or more), ECDSA | FIPS mode accepts smaller RSA keys. Strict mode refuses them. |

## Known Exceptions

FIPS mode does not approve these uses. The first three are read paths for data that a standard build or an older release wrote. AI Studio uses them until it writes the data again in an approved format. AI Studio never uses the last one.

| Use | Where | Notes |
| :-- | :---- | :---- |
| bcrypt verification | Passwords and secrets that a standard build stored | Replaced at the next login or use |
| scrypt key derivation | `v2:` secrets that a standard build wrote | Re-encrypted to `v3:` at startup in FIPS mode |
| AES-CFB decryption | Secrets older than the `v2:` format | Read only by the startup re-encryption |
| MD5 and SHA-1 | The MongoDB driver in the SSO identity broker | Used only for connections to MongoDB. AI Studio does not connect to MongoDB. |
