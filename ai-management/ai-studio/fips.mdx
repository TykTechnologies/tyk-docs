## Availability

| Edition | Deployment Type |
| :------------- | :---------------------- |
| [Community](/ai-management/ai-studio/overview#community-edition) & [Enterprise](/ai-management/ai-studio/overview#enterprise-edition) | Self-Managed |

FIPS 140-3 builds are available from Tyk AI Studio 2.3.0. Packages are available for both editions. Container images are available for the Enterprise Edition only.

## Overview

AI Studio and the Edge Gateway (the microgateway) are available as FIPS 140-3 builds. Tyk Gateway, Tyk Dashboard, Tyk Pump and Tyk MDCB have FIPS builds too. For the Tyk FIPS policy, refer to [FIPS Policy](/developer-support/release-types/fips-release).

The FIPS builds are FIPS 140-3 compliant. They use approved algorithms from a validated cryptographic module. The builds themselves are not certified products. A small number of non-approved read paths remain. Refer to [Known Exceptions](#known-exceptions).

The standard builds do not change. A database can move from a standard build to a FIPS build, and back. Refer to [Data Formats](#data-formats).

## The Validated Module

The FIPS builds use the **Go Cryptographic Module v1.0.0**. This module has [CMVP certificate #5247](https://csrc.nist.gov/projects/cryptographic-module-validation-program/certificate/5247). The build selects the module with `GOFIPS140=v1.0.0`.

A FIPS build starts in FIPS mode. In FIPS mode, TLS, hashing, HMAC, key derivation and encryption use the approved algorithms of the module.

## Packages and Images

| Component | DEB and RPM Package | Container Image |
| :-------- | :------------------ | :-------------- |
| AI Studio | `tyk-ai-studio-fips` (Community Edition), `tyk-ai-studio-fips-ee` (Enterprise Edition) | `tykio/tyk-ai-studio-fips` |
| Edge Gateway (server and `mgw` CLI) | `tyk-microgateway-fips` (Community Edition), `tyk-microgateway-fips-ee` (Enterprise Edition) | `tykio/tyk-microgateway-fips` |

- Packages are available for amd64, arm64 and s390x.
- Images are available for amd64 and arm64. Tyk builds the images from the Enterprise Edition packages, on the Tyk FIPS base image. Each image has a provenance attestation and an SBOM attestation.
- A FIPS package installs its files to the same paths as the standard package. Install only one of the two packages on a host.
- The FIPS images use the same paths, ports and settings as the standard images. They run as user ID 65532.

<Warning>
Packages with `-fips` names that Tyk published before release 2.3.0 are standard builds. Do not use them for a FIPS deployment. The `-fips` packages from release 2.3.0 are FIPS builds. Tyk checks each binary before the release.
</Warning>

### Install the Packages

The FIPS packages use the same package repositories and the same configuration as the standard packages. To install them, follow [Install Tyk AI Studio on Linux](/ai-management/ai-studio/installation/linux), and change the package names. For example, for the Enterprise Edition:

```bash
# Debian/Ubuntu
sudo apt-get install tyk-ai-studio-fips-ee
sudo apt-get install tyk-microgateway-fips-ee

# RHEL/CentOS/Amazon Linux
sudo yum install tyk-ai-studio-fips-ee
sudo yum install tyk-microgateway-fips-ee
```

### Use the Images with Helm or Docker

To use the FIPS images with the AI Studio Helm chart, change the image repositories in your values file. For the chart, refer to [Install Tyk AI Studio on Kubernetes](/ai-management/ai-studio/deployment-k8s).

```yaml
midsommar:
  image:
    repository: tykio/tyk-ai-studio-fips
    tag: v2.3.0

microgateway:
  image:
    repository: tykio/tyk-microgateway-fips
    tag: v2.3.0
```

With Docker or Docker Compose, use `tykio/tyk-ai-studio-fips:<version>` or `tykio/tyk-microgateway-fips:<version>` as the image.

## Check That FIPS Mode Is On

A FIPS build starts in FIPS mode, but an environment variable can turn FIPS mode off. Refer to [FIPS Modes](#fips-modes). Thus, the package name or image name does not prove that FIPS mode is on. Check the status that the process reports.

Each process reports three values:

| Value | Description |
| :---- | :---------- |
| `enabled` | `true` when FIPS mode is on. |
| `version` | The version of the Go Cryptographic Module, for example `v1.0.0-c2097c7c`. |
| `enforced` | `true` when the process refuses all non-approved algorithms (`GODEBUG=fips140=only`). |

You can see these values in three places:

- **Startup log**: AI Studio writes the line `FIPS 140-3: enabled=true version=v1.0.0-... enforced=false` when it starts. The Edge Gateway writes a `FIPS 140-3` log entry with the fields `enabled`, `version` and `enforced`.
- **Health endpoint**: `GET /health` on AI Studio and on the Edge Gateway returns a `fips` object with the three values.
- **Edge Gateways page**: Each Edge Gateway sends its status to AI Studio in its heartbeat. The **Edge Gateways** page shows the status of each edge, for example `FIPS: On (v1.0.0-c2097c7c)`. The details page of an edge shows the status under **FIPS 140-3 (reported by edge)**. An edge that has not sent a status shows `Unknown`. For more about edges, refer to [Manage Edge Gateway for Tyk AI Studio](/ai-management/ai-studio/manage-edge-gateway).

For example, the health endpoint of AI Studio returns:

```json
{"status": "ok", "fips": {"enabled": true, "version": "v1.0.0-c2097c7c", "enforced": false}}
```

The Edge Gateway also adds `"service": "microgateway"` to the response. For the health endpoints, refer to the [AI Studio API reference](/ai-management/ai-studio/ai-studio-swagger).

## FIPS Modes

The `GODEBUG` environment variable sets the FIPS mode of a FIPS build at run time.

| Variable | Default | Description |
| :------- | :------ | :---------- |
| `GODEBUG=fips140=on` | On in FIPS builds | FIPS mode. The process uses the approved algorithms of the module. |
| `GODEBUG=fips140=off` | - | Turns FIPS mode off, also in a FIPS build. The status shows `"enabled": false`. |
| `GODEBUG=fips140=only` | - | Strict mode. The process also refuses all non-approved algorithms. The status shows `"enforced": true`. Use this mode for tests. |

## Data Formats

A process in FIPS mode writes data in approved formats. Every build of AI Studio 2.3 reads the old formats and the new formats.

| Data | Standard Build Writes | FIPS Build Writes |
| :--- | :-------------------- | :---------------- |
| Secrets at rest (encrypted with `TYK_AI_SECRET_KEY`) | `v2:` format (scrypt and AES-GCM) | `v3:` format (PBKDF2-HMAC-SHA256 and AES-GCM) |
| User passwords, OAuth client secrets, Edge Gateway credential secrets | bcrypt | PBKDF2-HMAC-SHA256 |

### Secrets

When AI Studio starts in FIPS mode, it re-encrypts stored secrets to the `v3:` format. This work runs in the background. It includes the values on the **Secrets** page. It also includes encrypted values in other records, such as LLM API keys, webhook headers and Tyk Gateway connection tokens. Until the work is complete, AI Studio continues to read the older values. When the work is complete, AI Studio logs the number of values that it re-encrypted.

A standard build does not re-encrypt secrets.

### Passwords and Client Secrets

When a user logs in on a FIPS build, AI Studio replaces the bcrypt hash of the password with a PBKDF2 hash. It replaces the hash of an OAuth client secret the next time that the client authenticates successfully.

For more about secrets, refer to [Manage Secrets in Tyk AI Studio](/ai-management/ai-studio/secrets).

## Move an Existing Deployment to FIPS Builds

Do these steps when you change a deployment from standard builds to FIPS builds.

1. Take a database backup.
2. Make sure that your TLS endpoints, certificates and keys meet the [requirements](#tls-and-key-requirements).
3. If you use PostgreSQL, set it to use SCRAM-SHA-256 password authentication. Do not use `md5`.
4. Replace each plugin with a FIPS build of the plugin. Refer to [Plugins](#plugins).
5. Replace the AI Studio and Edge Gateway packages or images with the FIPS packages or images.
6. Start AI Studio in FIPS mode (the default). Let the re-encryption of secrets complete. Look for the log line that gives the number of re-encrypted values.
7. [Check that FIPS mode is on](#check-that-fips-mode-is-on) for AI Studio and for each Edge Gateway.
8. Optional: To test that no non-approved algorithm is in use, set `GODEBUG=fips140=only`.

<Note>
In strict mode (`GODEBUG=fips140=only`), AI Studio can read secrets that are older than the `v2:` format (AES-CFB) only during the startup re-encryption. Before that work is complete, a read of such a secret returns an error. Thus, start AI Studio one time in FIPS mode, and let the re-encryption complete, before you use strict mode.
</Note>

### TLS and Key Requirements

FIPS mode accepts only TLS 1.2 and TLS 1.3, with approved cipher suites and curves. These rules apply to the connections listed here:

- Connections to LLM vendors
- The connection between AI Studio and the Edge Gateways
- Plugins that use gRPC
- Your own TLS endpoints

These peers cannot connect in FIPS mode:

- A peer that offers only ChaCha20-Poly1305
- A peer that offers only X25519 key exchange

FIPS mode accepts the hybrid post-quantum key exchange X25519MLKEM768 of TLS 1.3.

Use these key types:

| Key | Permitted Types | Notes |
| :-- | :-------------- | :---- |
| TLS certificates | RSA (2048 bits or more), ECDSA (P-256, P-384, P-521), Ed25519 | FIPS mode and strict mode refuse other keys. |
| Plugin signing keys, JWKS of SSO identity providers | RSA (2048 bits or more), ECDSA | FIPS mode accepts smaller RSA keys. Strict mode refuses them. |

Options that skip TLS certificate verification are outside the scope of FIPS compliance. Do not use them in a FIPS deployment.

### Plugins

Each plugin runs as a separate process and does its own cryptography, such as TLS to an LLM vendor. A deployment is FIPS compliant only when each plugin is a FIPS build too. Build Go plugins with `GOFIPS140=v1.0.0`.

A plugin publisher can publish the FIPS build of a plugin version under the OCI tag `<version>-fips`. To install it, use that tag in the plugin command, for example `oci://<registry>/<repository>/<plugin>:1.4.0-fips`. For more about plugin publishing, refer to [Publish Tyk AI Studio Plugins](/ai-management/ai-studio/plugins/publishing).

In FIPS mode, AI Studio and the Edge Gateway log a warning when a plugin is not a FIPS build. They also log it for a binary that is not a readable Go binary. The warning starts with `FIPS 140-3 mode: starting a plugin that is not a FIPS build`. The plugin still starts.

### Native API Resource Signing Keys

AI Studio signs the resource IDs that the native API extensions of OpenAI and Anthropic return, such as batch IDs and response IDs. Each LLM has a signing key for these IDs. You can see the key in the **Native API resource IDs** section of the LLM page.

If an LLM shows `Derived from the API key (not upgraded yet)`, the key comes from the vendor credential. A key from a short or placeholder credential, such as `none` for Ollama, is easy to guess in all builds. Also, a key from a short credential is different in FIPS mode. Thus, IDs from a standard build do not verify in FIPS mode. The reverse is also true. Select **Rotate signing key** to give the LLM a hub-generated secret.

## Build From Source

To build FIPS binaries from the [AI Studio repository](https://github.com/TykTechnologies/ai-studio), run `make build-fips` in the repository root. This target builds AI Studio and the Edge Gateway, and checks each binary with `scripts/fips-verify.sh`. To build only the Edge Gateway server and CLI, run `make build-fips` in the `microgateway` directory.

To check a binary yourself, run `go version -m <binary>`. A FIPS build shows these settings:

- `GOFIPS140=v1.0.0-...`
- `DefaultGODEBUG` that contains `fips140=on`
- The `fips` build tag

The script `scripts/fips-verify.sh --fips <binary>` checks all three settings.

## Known Exceptions

FIPS mode does not approve these uses. The first three are read paths for data that a standard build or an older release wrote. AI Studio uses them until it writes the data again in an approved format. AI Studio never uses the last one.

| Use | Where | Notes |
| :-- | :---- | :---- |
| bcrypt verification | Passwords and secrets that a standard build stored | Replaced at the next login or use |
| scrypt key derivation | `v2:` secrets that a standard build wrote | Re-encrypted to `v3:` at startup in FIPS mode |
| AES-CFB decryption | Secrets older than the `v2:` format | Read only by the startup re-encryption |
| MD5 and SHA-1 | The MongoDB driver in the SSO identity broker | Used only for connections to MongoDB. AI Studio does not connect to MongoDB. |
